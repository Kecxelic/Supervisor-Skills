# 实验与洞察设计

设计超越排行榜数字、揭示模型能力深度洞察的实验。在 Benchmark 论文中，实验章节不是关于"证明我们的方法最好"，而是关于**揭示模型在哪里以及为什么失败，以及这对未来研究意味着什么。**

## 1. 基线模型选择

覆盖多个轴以进行全面比较。最少 10-15 个模型：

| 轴 | 类别 | 目的 |
|------|------|------|
| **开源 vs 闭源** | GPT-4o、Claude、Gemini vs LLaMA、Qwen、Mistral、DeepSeek | 专有与可获取模型的能力差距 |
| **模型规模** | 7B -> 13B -> 70B -> 100B+ | 能力如何随参数扩展 |
| **架构** | 仅解码器 vs 编码器-解码器；纯文本 vs 多模态 | 架构特定的优劣势 |
| **专业化** | 通用 vs 领域特定（代码、数学、视觉等） | 专业化训练是否迁移 |

询问用户："将评估哪些模型？是否覆盖上述所有四个轴？"

## 2. 评估协议

### 2.1 评估设置

定义模型如何与 Benchmark 交互：

| 要素 | 关键问题 | 指导 |
|------|----------|------|
| **输入格式** | 模型如何接收输入？提供什么上下文？ | 指定提示模板、输入结构和任何特殊格式 |
| **输出提取** | 模型输出如何解析和评分？ | 定义提取规则、解析逻辑和边缘情况处理 |
| **提示策略** | Zero-shot、Few-shot（1/3/5）、CoT、领域知识提示、工具使用 | 测试多种；报告哪些有帮助/有害 |
| **评估方法** | 自动指标、LLM-as-Judge、人工评估 | 使用 ≥2 种方法；验证 LLM-judge 与人工的一致性 |
| **指标选择** | 什么指标以及为什么？ | 论证指标选择；优先一个头条指标用于主排名，分解为次要 |
| **重复次数** | 每模型 1-5 次运行 | 非确定性设置报告均值 ± 标准差；报告模型内方差 |
| **温度** | 0 用于可复现，>0 用于多样性分析 | 记录选择 |

### 2.2 人类基线实验

如进行人类评估，指定：

| 要素 | 详情 |
|------|------|
| **参与者概况** | 多少人？背景/专业？招募标准？ |
| **实验协议** | 任务说明、时间限制、标注界面 |
| **评分者间信度** | 一致性指标（Cohen's κ、Fleiss' κ、ICC）及阈值 |
| **比较设计** | 相同样本由人类和模型分别评估 |

### 2.3 基线公平性

同等记录每个基线的优化努力。审稿人越来越警惕"基线弱化"——低优化竞争者超参数。每个基线应使用已知最佳配置。

## 3. RQ 驱动的实验结构

所有实验围绕研究问题组织。每个 RQ 驱动一个分析子节：

### RQ 分析模板

对每个 RQ，指定：

```
RQ[N]：[问题]
├── 假设：[预期发现]
├── 实验：[具体比较或分析]
├── 变量：[变化的 vs 控制的]
├── 指标：[测量的]
├── 可视化：[图或表类型]
└── 预期发现：[洞察]
```

### 常见分析类型

| 分析 | 揭示什么 | 可视化 | 优先级 |
|------|----------|--------|--------|
| **总体性能** | 通用能力概况 | 大表：所有模型 × 所有指标 | 必须 |
| **类别分解** | 各分类法性能 | 分组柱状图或热力图 | 必须 |
| **难度梯度** | 性能如何随难度退化 | 折线图（x=难度，y=分数） | 必须 |
| **错误分类法** | 模型犯什么类型的错误 | 堆叠柱状图、饼图 + 错误示例 | 高 |
| **模型行为偏差** | 模型是否有系统性倾向 | 分布密度曲线、校准图 | 高 |
| **人类 vs 模型** | AI 在哪里匹配/超越/落后 | 雷达图或配对比较柱状图 | 高 |
| **提示影响** | 策略如何影响性能 | 消融表（行=模型，列=策略） | 中 |
| **规模效应** | 模型大小如何影响能力 | 折线图（x=参数，y=分数） | 中 |
| **跨维度相关** | 哪些能力相关 | 相关热力图 | 可选 |

## 4. 总体性能表

论文中最大且最重要的表（通常 Table 2 或 3）：

```
| 模型 | 规模 | 总体 | [Dim1] | [Dim2] | [Dim3] | [SubDim1.1] | [SubDim1.2] | ... |
|------|------|------|--------|--------|--------|-------------|-------------|-----|
| GPT-4o | - | XX.X | XX.X | XX.X | XX.X | XX.X | XX.X | |
| Claude | - | XX.X | XX.X | XX.X | XX.X | XX.X | XX.X | |
| LLaMA-70B | 70B | XX.X | XX.X | XX.X | XX.X | XX.X | XX.X | |
| ... | | | | | | | | |
| 人类 | - | XX.X | XX.X | XX.X | XX.X | XX.X | XX.X | |
```

设计指南：
- 每列**加粗**最佳结果；**下划线**次佳
- 按类别分组模型（闭源/开源/专业化）
- 包含人类性能作为上界（如适用）
- 如有洞察，添加平均和最差情况行

## 5. "Finding X" 模式

<极其重要>
这是 Benchmark 论文的标志性写作技巧。每次主要分析后，提取并加粗一个编号 Finding：

**Finding 1.** Few-shot 学习和领域知识包含有助于 LLM，而 Chain-of-Thought 倾向于在较小模型上略微降低性能。

**Finding 2.** 所有测试模型在[特定子类别]上低于随机基线，揭示了[特定技能]的根本能力差距。

**Finding 3.** 模型规模单调提升[维度 A]性能，但对[维度 B]无显著影响，表明这些能力有不同的缩放性质。

每条 Finding 必须：
- **令人惊讶或非显而易见**，不只是"更大模型更好"
- **具体**，命名具体模型、类别或条件
- **可操作**，暗示未来研究应解决什么
- **有数据支撑**，直接由上方分析支持

每条 Finding 的**微结构模板**：

```
[含数据的分析段落……]

**Finding N.** [引导句：一句话中的关键结果。]
[证据：具体数字、模型、条件。]
[限定：范围和边界条件。]
[前瞻指针：这对未来工作意味着什么。]
```
</极其重要>

## 6. 案例研究设计

包含 2-4 个案例研究以增加定性深度：

| 类型 | 目的 | 格式 |
|------|------|------|
| **成功案例** | 展示 Benchmark 区分能力 | 强模型 vs 弱模型在同一输入上 |
| **失败案例** | 揭示具体模型局限 | 模型输出 + 失败位置/原因标注 |
| ** surprising 案例** | 突出反直觉行为 | 设定期望 -> 展示意外结果 |
| **边缘案例** | 测试能力边界 | 翻转正确 -> 错误的最小变化 |

## 7. 伴随方法实验（如适用）

如提出伴随方法（来自设计）：

- 在新 Benchmark 上与基线比较
- 方法组件消融研究
- 各类别改进分析（方法在哪里帮助最多？）
- 泛化测试（改进是否迁移到其他 Benchmark？）
- **下游应用验证**（Benchmark/方法能否用于改进真实世界性能？如 VisJudge-Bench 通过下游可视化质量改进验证）

## 8. 研究机会

从 Findings 中推导 3-5 个未来方向。典型方向：

- 如何在[空白领域]增强模型能力
- [任务]的人机协作模式
- Benchmark 扩展（新模态、语言、领域、难度级别）
- 受发现启发的训练方法改进
- 为什么[特定 Finding]会发生的理论理解
