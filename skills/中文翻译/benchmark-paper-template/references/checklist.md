投稿前最终质量门。一个缺失的要素、一个被遗忘的管线图、缺失的 Finding 摘要或没有 Benchmark 对比表，都可能让论文在顶会丢掉录用。

## 1. Introduction 检查单

- [ ] **运行示例（Figure 1）**：一张精心设计的图，用具体示例展示评估空白？
- [ ] **评估空白**：已有 Benchmark 的关键盲区清晰陈述（≤3 点，具体非模糊）？
- [ ] **Benchmark 对比（Table 1）**：与 ≥5 个已有 Benchmark 在关键维度上比较？
- [ ] **研究问题**：2-3 个 RQ 明确陈述？
- [ ] **设计考量**：设计理由和关键选择已解释（为什么，不仅是是什么）？
- [ ] **贡献**：2-4 条贡献列出，每条与一个 RQ 和一个论文章节对齐？
- [ ] **叙事流**：背景 -> 空白 -> 我们的方案 -> 预览发现 -> 贡献？
- [ ] **具体数字**：Introduction 中提到规模、模型数量和关键指标？

## 2. Benchmark 章节检查单

- [ ] **设计目标**：G1-G4（或自定义目标）明确陈述策略？
- [ ] **任务范围**：评估和不评估什么的清晰边界，含排除理由？
- [ ] **管线图（Figure 2）**：清晰的构建管线流程图，含步骤、数据计数和质量门？
- [ ] **管线步骤**：每步有明确的输入、操作和输出？
- [ ] **质量控制**：QC 策略描述（标注者间一致性、专家审查、验证分数）？
- [ ] **数据集统计（Table 2）**：全面统计呈现（总数、各划分、各类别）？
- [ ] **分布图**：分类法分布、难度分布、长度分布可视化？
- [ ] **数据示例**：2-3 个代表性示例以图展示？
- [ ] **分类法覆盖**：数据分布覆盖所有分类法类别且合理平衡？

## 3. 实验章节检查单

- [ ] **模型覆盖**：基线覆盖开源/闭源、多种规模、不同架构（≥10 个模型）？
- [ ] **总体性能表（Table 3）**：全面表格，所有模型 × 所有指标，标记最佳/次佳？
- [ ] **细粒度分析**：超越总评的多维分析，按 RQ 组织？
- [ ] **错误分类法**：分析模型犯什么类型的错误（不只是准确率数字）？
- [ ] **人类 vs 模型**：包含人类性能基线？（如确实不适用，标记 N/A 并说明理由）
- [ ] **案例研究**：2-4 个定性示例展示具体模型成功/失败？
- [ ] **Finding X 摘要**：每次主要分析后提取并加粗关键洞察？
- [ ] **研究机会**：讨论未来方向，基于 Findings？

## 4. 结构与完整性检查单

- [ ] **逻辑线**：论文遵循 空白 -> Benchmark -> 评估 -> 洞察 -> 机会？
- [ ] **开源**：代码和数据已发布（或将发布）？摘要或贡献中有链接？
- [ ] **数据托管**：数据集托管在专门平台（Hugging Face、Kaggle、OpenML、Dataverse），无需邮件联系作者即可获取？
- [ ] **许可证**：代码和数据均明确指定许可证？
- [ ] **局限性**：诚实讨论 Benchmark 局限和范围限制？
- [ ] **伦理**：讨论潜在危害、偏差、个人隐私暴露、知情同意和负责任使用指南？
- [ ] **数据表/数据卡**：包含收集过程、预期用途和局限的结构化文档（附录或补充材料）？
- [ ] **Related Work**：与已有工作系统比较，含对比表？
- [ ] **附录**：补充材料包含完整结果、标注指南、更多示例、使用的提示？
- [ ] **可复现**：足够详细使另一团队能复现构建和实验？提供可执行评估脚本？
- [ ] **统计严谨**：多次运行报告均值 ± 标准差？适当时做统计显著性检验？
- [ ] **污染缓解**：记录防止训练数据泄漏的策略？
- [ ] **维护计划**：谁维护 Benchmark？反馈渠道？更新/退役标准？
- [ ] **页面预算**：论文在会议页面限制内（正文）？
- [ ] **参考文献**：所有引用工作已验证并按会议风格格式化？

## 严重性分级

检查所有项目后，分类问题：

| 严重性 | 定义 | 行动 |
|--------|------|------|
| **Critical** ✗✗ | 缺失核心要素（无管线图、无 Finding 摘要、无对比表） | 必须投稿前修复 |
| **Major** ✗ | 存在但不充分（基线太少、QC 描述薄弱、空白模糊） | 强烈建议修复 |
| **Minor** ~ | 打磨级（图美观、措辞、附录顺序） | 有时间则修 |

呈现汇总：
```
投稿前判定：[就绪 / 未就绪]

Critical 问题：[数量]，[列表]
Major 问题：   [数量]，[列表]
Minor 问题：   [数量]，[列表]
```

## 检查单之后

- **如 Critical 问题仍存在**：帮助用户修复，路由回相关子技能（如缺失管线图 -> 构建管线概念）
- **如全部通过**：确认就绪并提醒：
  - 会议特定格式和模板
  - 补充材料准备
  - 投稿前合作者审查
  - Camera-ready 准备时间线（如被录用）
