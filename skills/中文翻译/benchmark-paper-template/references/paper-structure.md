组织和写作 Benchmark/评估论文。Introduction 是整篇论文的"压缩版"，其叙事轴线不是"关键想法 / 机制"而是**"评估空白 + Benchmark 设计理由"。**

## Introduction：六部分框架

Introduction 是整篇论文的"压缩版"。其叙事轴线不是"关键想法 / 机制"而是**"评估空白 + Benchmark 设计理由"。**

Introduction 应遵循此确切逻辑链。每部分约对应一段：

### 第 1 部分：背景与核心场景（约 1 段）
- 确立更广泛任务/领域在真实场景中的重要性
- 展示领域已有快速进展（引用近期进展）
- 用精心设计的**运行示例（Figure 1）**说明任务复杂性及人类专家如何处理
- **Figure 1 是整篇论文最重要的图之一，必须精心打磨**
- **语调**：权威，引用知名工作

> **参考**：StatQA 使用完整的统计分析工作流；nvBench 2.0 展示歧义查询的多种合理解读；VisJudge-Bench 对比保真度/表达力/美学的正反例。

### 第 2 部分：已有 Benchmark 的局限，空白（约 1 段）
- 调查已有 Benchmark 测量什么，公平承认其贡献
- 识别它们共享的隐含假设，使之显式
- 阐述评估盲区（≤3 点，具体非模糊）
- **强烈推荐**：提供 Benchmark 对比表（Table 1），逐项比较特征维度使空白不言自明
- **这是最重要的一段。** 应让读者想："我从没考虑过这个，但显然很重要。"

> **参考**：nvBench 2.0 Table 1 在 6 个维度上比较 7 个 Benchmark；VisJudge-Bench Table 1 在 3 个评估维度上比较 7 个 Benchmark。

### 第 3 部分：研究问题（约 1 段）
- 将空白转化为 2-3 个具体研究问题
- RQ 覆盖应跨越：(1) 如何构建合适的 Benchmark？(2) 当前模型的能力边界在哪里？(3) 模型与人类专家的差距是什么？
- RQ 锚定整个实验章节

> **参考**：StatQA：Q1 如何评估？Q2 LLM 有多强？Q3 人类 vs LLM？

### 第 4 部分：设计考量（约 1 段）

<极其重要>
这是 Benchmark 论文独有的段落。在介绍你的方案之前，先阐述"一个好的 Benchmark 应具备什么属性"，这为你的设计选择提供理由。
</极其重要>

- 明确陈述设计要求（如多样覆盖、细粒度诊断、可扩展、质量保证）
- 这为 Benchmark 设计方式提供逻辑基础

> **参考**：nvBench 2.0："此 Benchmark 应包含多样的歧义查询、多种有效输出、推理路径和广泛的领域覆盖。"

### 第 5 部分：我们的 Benchmark + 关键发现预览（约 1-2 段）
- 正式介绍：Benchmark 名称、规模、关键设计选择
- 用 1-2 句话突出构建方法论创新
- 引用 Figure 1 和 Table 1
- 摘要 2-3 个最令人惊讶的实证发现以吸引读者
- 使用具体数字："我们在 6 个维度上评估了 15 个模型"
- **语调**：自信但精确

> **参考**：StatQA："我们的关键想法是反转这个过程，基于目标答案 A 合成问题 Q。"

### 第 6 部分：贡献（约 1 段，列表）
通常 3-4 条贡献，各映射到一个论文章节：

1. 我们识别[空白]并提出[名称]，首个针对[能力]的 Benchmark。（-> §1-2）
2. 我们设计[管线创新]，达到[质量/规模指标]。（-> §2）
3. 我们对[N]个模型进行全面评估并揭示[关键发现]。（-> §4）
4. （可选）我们提出[伴随方法]，将[指标]提升[幅度]。（-> §3）

## 关键 Introduction 图表

### Figure 1：运行示例（必须有）
论文中最重要的图。要求：

- 用一个具体示例展示评估空白
- 展示已有评估遗漏什么 vs 你的评估捕获什么
- 自包含，读者应仅从此图就能把握论文核心想法
- 放在第 1-2 页（尽可能在折叠线上方）

**设计模式：**
- **分屏视图**："已有评估"（左）vs "我们的评估"（右）
- **走查**：一个输入 -> 突出多个评估维度
- **对比**：同一模型输出被旧标准 vs 新标准评分

### Table 1：Benchmark 对比（必须有）
与 5-8 个已有 Benchmark 比较。最右列应是你的关键差异点：

```
| Benchmark | 年份 | 规模 | [Dim1] | [Dim2] | [Dim3] | [你的关键特征] |
|-----------|------|------|--------|--------|--------|----------------|
| Prior-1   | 20XX | N    | ✓      | ✗      | ✓      | ✗              |
| Prior-2   | 20XX | N    | ✓      | ✓      | ✗      | ✗              |
| **我们**  | 2025 | N    | **✓**  | **✓**  | **✓**  | **✓**          |
```

## 正文章节结构

### 第 2 节：提出的 Benchmark（3-4 页）

```
2.1 设计目标与任务范围
    - 明确陈述 G1-G4
    - 定义范围内 vs 范围外

2.2 Benchmark 构建管线
    - 管线概述段落
    - Figure 2：管线流程图（必须有）
    - 详细步骤，含输入 -> 操作 -> 输出
    - 质量控制措施
    - 标注协议（如涉及人工标注）

2.3 Benchmark 特征
    - Table 2：数据集统计（划分、类别、规模）
    - Figure 3-4：分布图（分类法、难度、长度）
    - Figure 5：数据示例（2-3 个代表性样本）
    - 与已有 Benchmark 在规模和覆盖上比较
```

### 第 3 节：专用模型（1-2 页，可选）

```
3.1 动机，Benchmark 如何使模型改进成为可能
3.2 方法，训练信号 + 优化技术
3.3 实现细节
```

**此节回答**："这个 Benchmark 不仅评估，还帮助改进模型。"

### 第 4 节：实验与实证发现（4-5 页）

```
4.1 实验设置
    - 模型（按类型分组）、指标、提示、实现

4.2 总体性能
    - Table 3：所有模型 × 所有指标（论文中最大的表）
    - 加粗最佳，下划线次佳
    - 分析后给出 Finding 1

4.3 细粒度分析（按 RQ 组织）
    - RQ1 分析 -> Finding 2
    - RQ2 分析 -> Finding 3
    - RQ3 分析 -> Finding 4
    - 每个有支撑图表

4.4 案例研究
    - 2-4 个示例，含定性分析
    - 成功案例、失败案例、 surprising 案例
```

### 第 5 节：讨论与研究机会（约 1 页）

基于 Findings 讨论：
- 如何在识别的空白上增强模型能力
- 人机协作模式
- Benchmark 扩展方向（新模态、语言、领域）
- 当前 Benchmark 的局限

### 第 6 节：Related Work（约 1 页）

组织为 2-3 个子节：
- [任务特定] Benchmark
- [领域] 评估方法论
- [相关能力] 在大语言模型中

**包含对比表**（可以是扩展的 Table 1 或聚焦方法论差异的新表）。

**位置说明**：Related Work 可在实验前或后。实验前（如 VisJudge-Bench）强调定位；实验后（如 StatQA、nvBench 2.0）让发现先说话。

### 第 7 节：结论（约 0.5 页）
- 1-2 句重申空白和 Benchmark
- 摘要关键发现（引用 Finding 编号）
- 重申开放问题和未来方向

## Benchmark 论文关键写作技巧

1. **"Finding X" 摘要**：每次主要分析后加粗高亮（见实验参考）
2. **设计理由优于描述**：对每个选择解释为什么，不只是是什么
3. **具体数字**："我们在 6 个维度上评估了 15 个模型"而非"许多模型"
4. **主动定位**："首个……的 Benchmark" / "不同于已有工作，我们……"
5. **示例驱动论证**：始终将抽象声称与具体示例配对
6. **附录策略**：将详细内容移入附录（完整结果、标注指南、更多示例、使用的提示）

## 附录规划

Benchmark 论文的标准附录章节：
- A：完整实验结果（所有模型 × 所有指标，未删节）
- B：标注指南和界面截图
- C：更多数据示例
- D：评估使用的提示
- E：扩展的 Related Work 或分类法细节
- F：伦理考量和数据表
