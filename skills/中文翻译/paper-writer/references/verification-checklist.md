# 交付验证检查单

## 目录

1. 步骤 1：来源回溯检查
2. 步骤 2：内联检查（文献、事实、证据匹配、跨章节、AI 痕迹、公式和表格、交付格式）
3. 失败时

交付前运行。整篇论文显式走每项；单节或单段心算同样通过。

## 步骤 1：来源回溯检查

逐声称过草稿，对每个事实性陈述问：这从哪里来？唯一可接受的答案是用户材料、本次会话检索结果或 L0 领域常识（无数字、人名、比较）。

- 无法追溯到这三个来源之一的声称被推定为模型记忆：删除它、重写句子去掉该声称或立即搜索真实来源。
- 绝不通过插入方括号注释解决任何东西；解决永远是搜索、重写或删除。

## 步骤 2：内联检查

### 2.1 文献

> 引用**存在性和元数据**在独立验证通过触发时由其负责（整篇论文、终稿模式或 3 条以上引用；验证阶梯中的触发表为权威）。
> 以下三项作为轻量片段的内联后备；独立通过运行时其状态优先。步骤 2 的其余部分始终内联检查。

- [ ] 每个正文引用标记可追溯到用户材料或本次会话检索？
- [ ] 无从模型记忆生成的参考文献？
- [ ] 无对被引工作的编造方法描述（将综述引用为"元分析"）？
- [ ] 使用来源处有正文标记（不是只有未引用的参考文献列表）？
- [ ] 参考文献章节已打印，编号与正文双向对应？
- [ ] 每个条目有作者、标题、会议、年份（不可确认条目已删除；非必要缺失字段已省略）？
- [ ] 引用格式一致（默认数字引用序，或用户要求的风格）？

### 2.2 事实

- [ ] 制度细节（政策规则、项目机制）全部来自用户输入，无补充？
- [ ] 案例引用号和法条号仅来自用户输入，绝不来自记忆？
- [ ] 科学比较值有来源？
- [ ] 无编造统计量（协变量 p 值、聚合指数）？
- [ ] 无编造程序细节：量表条目数、锚点、知情同意程序、软件版本、实施日期、缺失率、实现参数？
- [ ] 无用户未提及的应用场景？
- [ ] 无用户未描述的机制、物理原理或因果解释？
- [ ] 无用户未给的量级或规模描述（数百个、少于十个、十倍、数量级）？

### 2.3 证据匹配

- [ ] 每个强判断有证据或显式边界？
- [ ] 无元数据级（L3）来源写成全文级声称？
- [ ] 用户数据按其性质呈现（真实结果 vs 预期结果）？
- [ ] 贡献声称可追溯到实验或图？
- [ ] 草稿模式计划数据限于表格并标记为计划数据？

### 2.4 跨章节

- [ ] Discussion 解释为什么，不重述 Results 的什么？
- [ ] 结论回答 Introduction 的问题，不逐节回顾？
- [ ] 摘要和结论不是换词重复？
- [ ] 同一发现不超过三个章节出现？

### 2.5 AI 痕迹与清洁度

- [ ] 已对照 AI 语调护栏列表扫描？
- [ ] 无证据不足的膨胀词（innovative、pioneering、groundbreaking）？
- [ ] 动词强度匹配证据强度？
- [ ] 无内部脚手架泄漏到正文？
- [ ] 零方括号占位标签，任何种类、任何变体？
- [ ] 无流程前言（"让我先分析一下……"、"基于收集的证据……"或任何语言的等价物）？

### 2.6 公式和表格

- [ ] 显示数学用 `$$...$$`，行内用 `$...$`，无裸下标或 HTML 标签？
- [ ] 符号解释与公式的符号精确匹配？
- [ ] 结构化数据在表格中，不在流水正文里？
- [ ] 表格有标题、表头、单位；标题未融入正文？
- [ ] 草稿模式占位表结构完整（表头和单位，值单元格 `--`），不是模糊的"table pending"？
- [ ] 论文正文中无 markdown 加粗、斜体或 emoji？

### 2.7 交付格式（整篇论文和多节草稿）

- [ ] 产品需要文件交付吗？（单段或单节：对话输出足矣，跳过此块）
- [ ] 如需文件：草稿写入工作区为 Markdown 或 LaTeX？
- [ ] 如需文件：工作台账（证据台账、追溯表）在独立文件中，未嵌入正文？

## 失败时

- 失败项：修复后交付。
- 无用户材料无法修复：在交付备注中如实说明缺口；绝不将草稿冒充为终稿。
- 终稿模式有任何失败：不称为投稿就绪。
