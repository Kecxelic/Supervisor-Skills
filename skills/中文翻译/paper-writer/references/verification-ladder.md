# 引用验证阶梯

## 目录

1. 为什么验证必须独立
2. 能力阶梯
3. 何时触发独立通过
4. 验证器对每条引用做什么
5. 状态等级和解决路由
6. 诚实边界
7. 收敛规则

本文件仅管理一类幻觉：生成正文中的引用是否真实且忠实引用。它不替代其他交付检查。

## 1. 为什么验证必须独立

多数自审查在产生文本的同一上下文中进行。对于引用幻觉这几乎无用：从记忆写出"Smith et al. (2021) proposed X"的模型在被要求复查时会查阅同一记忆并确认。生成和审查是一个认知行为共享一个错误。

引用幻觉（编造的参考文献、交换的作者或年份、错误标识符、元数据被当作全文引用）也是最容易机械证伪的幻觉类：一条引用要么在检索中出现要么不出现；元数据要么匹配要么不匹配。这正是值得外包给独立步骤的部分，使防御建立在机械检索而非模型对自身诚实的基础上。

## 2. 能力阶梯

**纪律永不降级；只有验证机制降级，任何降级都须在交付备注中向用户披露。**

- **第 1 档，全新上下文验证器（首选）。** 如环境能生成干净上下文的子代理，派一个。其输入仅是正文（含引用标记）和参考文献列表。它不接收起草推理，因此写作者的信心不能污染检查。它用会话的文献检索能力验证每个条目。
- **第 2 档，同上下文接地。** 无子代理，但有检索（学术搜索工具、网页搜索或 shell 访问公共 API 如 Crossref、Semantic Scholar、arXiv、DBLP）。从实际检索响应重新推导每个参考文献条目，绝不从记忆，并对照检索返回检查每个声称。弱于第 1 档；如实说明。
- **第 3 档，闭卷。** 完全无检索。则：仅引用用户提供的参考文献；确认每个仅在校内级别引用；不添加其他参考文献；并在交付备注中声明未执行独立验证。

对于 API 覆盖差的文献（如大量中文会议文献），网页检索比索引元数据弱一档；将其结果视为 L3 并在重要时说明。

## 3. 何时触发独立通过

四个互斥档位，无中间地带：

| 情况 | 独立通过 |
|---|---|
| 整篇论文或多节草稿，或终稿模式 | **强制**，不论引用数量 |
| 否则，累计引用 3 条或以上 | **强制** |
| 否则，单段或短节 2 条或以下引用 | 可跳过；内联交付检查单覆盖 |
| 完全无引用 | 不触发 |

阈值设在 3 是因为 Introduction 和 Related Work 几乎立即超过它；只有真正轻量的片段落到内联侧。如此处任何陈述与技能自身文本冲突，此表优先。

## 4. 验证器对每条引用做什么

对参考文献列表中的每个条目：

**步骤 1：存在性和元数据。** 至少用三种查询形式搜索：完整标题；作者加关键词加年份；仅核心关键词。比较标题、作者、年份、会议与检索返回。

区分**"未找到"和"无法搜索"**。仅正常检索响应在三种以上查询形式下零命中才算未找到。工具错误、超时、速率限制或系统性空响应意味着搜索本身失败：评级 INCONCLUSIVE，绝不 NOT_FOUND。一次基础设施 hiccup 绝不能删除一条真实引用。

**步骤 2：引用强度，回到引用处。** 正文说"Author et al. addressed Y"是校内级别：匹配元数据足矣。正文说"achieved 92 percent on benchmark B"或描述其管线是全文级别：元数据无法支撑；评级 OVERCLAIM，除非用户提供了确实包含此内容的全文或摘要。

## 5. 状态等级和解决路由

| 状态 | 含义 | 解决 |
|---|---|---|
| **VERIFIED** | 找到；元数据匹配；校内级别引用 | 保留 |
| **METADATA_MISMATCH** | 工作存在但作者、年份或会议不同 | 从检索更正条目；如检索后端自身与多个来源或常识矛盾（经典论文日期在未来），不要盲目信任：暂停条目让用户决定 |
| **NOT_FOUND** | 正常检索，3 种以上查询形式零命中 | 删除引用及其支撑的句子，或通过检索找真实替代；绝不作为事实保留 |
| **OVERCLAIM** | 工作真实但正文声称超出可用级别 | 将句子降级到校内级别（"X et al. addressed Y"） |
| **INCONCLUSIVE** | 工具错误、超时、速率限制、系统性空响应 | 既不通过也不删除；重试，如持续则暂停条目并在交付备注中交给用户 |

暂停条目在白话交付备注中列出。任何状态绝不通过在正文中插入方括号标签解决。

## 6. 诚实边界

此通过能捕捉：编造的参考文献（NOT_FOUND 是其核心价值）、交换的元数据、以及元数据被当作全文引用（OVERCLAIM）。

它不能捕捉：真实的校内级别引用其底层声称本身有误（需要全文，属于证据匹配检查，不在此处）；以及非引用编造如编造的制度细节或数字（由写作时证据纪律预防，不在此处修复）。

元数据更正和 OVERCLAIM 判断仍涉及模型判断，检索后端本身也可能有误；METADATA_MISMATCH 保障正是为此而设。此通过加固引用层；它不是全面保证。

## 7. 收敛规则

交付仅在**无未解决问题条目残留**时进行。这不等于"全部 VERIFIED"：条目在 VERIFIED、更正、删除、降级到校内级别、或明确暂停给用户时算已解决。未解决的 NOT_FOUND、METADATA_MISMATCH 或 OVERCLAIM 条目路由回写作者做针对性修复（仅受影响句子，非重写），然后重新验证。
