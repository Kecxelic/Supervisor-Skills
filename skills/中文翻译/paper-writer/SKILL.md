# 论文写作者

## 概述

本技能将研究者的想法和材料转化为可投稿论文正文。一段可以，整篇也可以。

它不是大纲生成器，也不是写作教程。它写正文，在一个不可协商的前提下：每个写下的字都必须可追溯到证据。作者拥有实质内容（想法、设计、结果、结论）；本技能只拥有这些实质内容的语言实现，不多一分。

## 硬规则

以下对本技能执行的每个任务均有效：

1. 每个事实性声明有三个来源之一：用户的材料、本次会话的已核验检索、或不含数字、人名、比较的领域常识。模型记忆永不是来源。
2. 交付正文包含零方括号占位标签，任何种类。缺少来源的声称通过搜索、重写或删除来解决，绝不通过标记。
3. 用户未提供的具体细节不写：不编造场景、机制、量级、程序或标识符。
4. 声称强度永不超过证据强度。
5. 真实结果与计划或预期结果措辞不同，绝不混用。
6. 内部规划绝不泄漏到输出中。

完整纪律，包括证据层级和证据台账：见 references/evidence-discipline.md。

## 何时使用本技能

- "把这个想法写成一段英文 Introduction。"
- "按某个会议的风格起草 Discussion。"
- "写一篇完整的论文初稿。"
- "把这些笔记变成方法章节。"
- "写一个摘要。"

## 何时不用本技能

- 用户明确想要 Introduction：`intro-drafter` 负责该节（本技能自动路由到那里）。
- 论文是仍在规划中的 Benchmark 论文：先用 `benchmark-paper-template`，再回来写正文。
- 已有正文需要语言润色：`paper-polish`。
- 逻辑骨架未定：先用 `tech-paper-template`。
- 想法本身未经验证：`idea-evaluator`。

## 能力检查（每会话一次）

本技能使用两种环境能力，缺失时诚实降级：

- **文献检索**：有学术搜索工具则用；否则用网页搜索覆盖学术索引；再否则用 shell 访问公共 API（Crossref、Semantic Scholar、arXiv、DBLP）。如果都没有，闭卷操作：只引用用户提供的参考文献，将引用声称保持在校内级别，并在交付备注中披露无法独立检索。
- **全新上下文子代理**：用于独立引用验证。没有则降到同上下文接地档。阶梯及其披露规则：见 references/verification-ladder.md。

上述证据规则永不降级；只有验证机制降级，任何降级都须披露。

## 工作流

六个阶段。整篇论文显式走全部；单节以更轻形式走相同阶段，但绝不跳过证据或审查。

### 阶段 1：范围

快速确定三件事，不审问用户：

- **粒度**：整篇论文（产出工作文件：证据台账、章节蓝图，然后草稿）vs 单节或单段（心算盘点，直接交付正文）。
- **范式**，按研究方法判断，不按学科名：实验、benchmark、模型、算法意味着 STEM；文本分析、档案、概念论证意味着人文学科；问卷、访谈、回归、田野调查意味着经验社会科学；工具变量、双重差分、面板数据意味着经济学；法律、案例、教义意味着法学；对已有研究的综合意味着综述。不清晰时：问一个关于核心方法和目标会议的问题。
- **模式**：草稿（默认；表格中允许结构性占位）vs 终稿（用户说投稿就绪；不允许任何待处理项）。

### 阶段 2：证据

在任何文字之前，先理清证据库包含什么。

1. 盘点用户材料。材料在工作区文件中时，读文件并记录路径；不要让用户粘贴你能读到的东西。
2. 用两到三轮不同关键词的检索构建文献池（目标规模：整篇论文约二十篇工作；覆盖重要，数字不重要）。
3. 识别证据缺口：哪些计划中的声称目前没有 L1-L3 来源？

整篇论文产出书面证据台账；单节心算同样检查。模板、层级和门禁：references/evidence-discipline.md。

**门禁**：无 L0-L3 来源的声称不作为事实写出。先搜索；如果两三个关键词变体找不到，重写句子去掉该声称或删除。

### 阶段 3：蓝图

按范式和章节路由：

| 情况 | 路由 |
|---|---|
| STEM Introduction | 交给 `intro-drafter`（六段式内部脚手架） |
| STEM 其他章节 | references/section-guidance.md 内容合同 |
| 非 STEM，任何章节 | 在 CER 骨架上逐段规划：声称（读者应相信什么）、证据（什么支撑它，哪个层级）、推理（为什么该证据支撑声称）、角色（激发、定位、提出、执行、呈现、解释、限定或连接） |
| Benchmark 论文 | 在 `benchmark-paper-template` 中规划，再回来 |

整篇论文产出章节蓝图作为工作文件：章节、角色、主要判断、证据 ID、开放缺口。对 STEM 工作，端到端检查逻辑链：局限喂入关键想法，关键想法引出挑战，模块一一回应挑战，贡献覆盖模块。断裂在计划中修复，绝不在正文中粉饰。

全部内部。不出现在交付物中。

### 阶段 4：起草

从蓝图写出流畅正文，带来源思考：每段之前，内部确定它将声称什么以及哪个来源支撑每个声称；无来源的声称在规划时排除。写干净文本，不嵌入任何标记。

硬性写作规则：

1. **绝不从模型记忆生成内容。** 仅有三种合法来源（用户、检索、L0）。不确定的事实通过检索验证；验证失败则重写或删除，绝不标记。
2. **证据层级限制声称强度。** L1 支撑任何声称；L2 支撑方向性摘要；L3 仅支撑引用级声称；L4 不支撑任何东西。
3. **不编造具体细节。** 五类红旗（场景、机制、量级、程序、标识符）是禁单；省略永远胜过看似合理的编造。
4. **区分真实与计划结果。** 确认结果："我们观察到"、"结果显示"。预期或未确认："作者报告"、"初步结果提示"。
5. **绝不为作者过度声称。** 无证据时："可能"、"显示出前景"、"预计"。
6. **每节各司其职，只做一次。** Introduction 让读者在意、展示空白、陈述目标。方法使另一研究者可复现。结果报告观察不解释为什么。讨论解释为什么、连接已有工作、承认局限。结论回答 Introduction。摘要是最后写的独立微型论文。同一发现至多出现在三个章节。
7. **输出中无内部脚手架。** CER 骨架、范式判断、链条检查全部静默。

### 阶段 4.5：红旗（写作中的停止信号）

| 念头 | 正确做法 |
|---|---|
| "我记得这个量表有 10 个条目" | 停。不确定。省略条目数 |
| "我记得这篇论文用了元分析" | 停。未看全文。仅引用级："X 等（年份）研究了 Y" |
| "我记得这个案例的引用编号" | 停。差一位就是错。省略标识符 |
| "这个材料的导电率大概是……" | 停。除非用户给了数字，不做跨材料比较 |
| "这个国家的政策是这样的……" | 停。制度细节仅按用户描述的写 |
| "背景应该提一下该领域的发展" | 停。超出 L0 的背景声称需要 L1-L3 来源。搜索；找不到就不写 |
| "读者期望这里有知情同意细节" | 停。未提供即省略 |
| "一个看起来完整的表格更专业" | 停。单元格中的 `--` 比编造值安全 100 倍 |
| "这段讨论应该更充实" | 停。用证据充实，不编造机制。短而准确胜过长而空洞 |
| "这方法可以应用于太阳能农场/自动驾驶……" | 停。用户未命名此场景 |
| "它之所以有效是因为频谱分解/梯度耦合……" | 停。用户未描述此机制 |
| "目标相差十倍/少于十个像素/数百个类别" | 停。用户未给此量级 |
| "一个具体的失败案例可以说明这点" | 停。不编造领域小故事。用用户自己的描述 |

### 阶段 5：审查

三部分，按序：

1. **来源回溯检查加内联检查清单。** 走 references/verification-checklist.md：事实、证据匹配、跨章节纪律、AI 痕迹扫描、公式和表格、交付格式。
2. **独立引用验证。** 整篇论文、终稿模式或三条以上引用时强制；全新上下文子代理仅接收正文和参考文献列表，通过检索逐条核验。状态、解决路由和降级阶梯：references/verification-ladder.md。交付在无未解决问题条目之前不进行。
3. **知晓审查不能做什么。** 同上下文审查可靠地捕捉机械问题（编号、格式、跨章节重复）。它不能可靠地捕捉自身的语义编造；一个编造了场景的模型在重读时会确认该场景。真正的防御是阶段 2-4 的写作时证据门禁；审查阶段是后盾，引用层获得独立通过恰恰因为它是唯一可以机械外包的层。

### 阶段 6：交付

交付物与禁令：references/prose-delivery.md。

- 单节或单段：对话中的正文，有引用时附参考文献列表，至多三行备注。
- 整篇论文：稿件写入工作区文件（Markdown 或 LaTeX），含参考文献；证据台账和蓝图保留为独立工作文件，按需提供，绝不嵌入稿件。
- 任何能力降级（无检索、无子代理）在备注中说明。

## 主动文献检索

不要等用户交付每一条参考文献。稀疏引用读起来像观点文章，审稿人会拒稿。

引用密度（指导，非配额）：完整 Introduction 通常织入 15-25 条参考文献；单段缺口或背景段 3-6 条；Related Work 15-30 条；方法 3-8 条（引用的方法、数据集、协议）；讨论 5-15 条；整篇论文约 20-40 条。

**先检索后写，不是先写后检索。** 起草任何章节前，从不同角度运行三到五轮检索：核心术语；方法或模型名；应用领域；会议或作者名。检索到的工作是论证组织的材料，不是事后附加的装饰。

检索返回元数据（L3），仅支撑引用级声称："Author 等使用 Y 处理了 X"可以；"他们的方法依赖三阶段管线"或具体数字不可以，除非用户提供了摘要或全文。手中只有 L3 但需要全文级内容：写引用级版本，在备注中告诉用户哪个来源能解锁更强的句子。

如果起草的章节明显引用不足，回去再搜一轮，然后织入真实发现。绝不用占位符填补缺口。

## 引用与参考文献

默认风格为数字引用序加参考文献章节，与正文双向对应。条目格式、作者规则、缺失字段处理和替代风格（APA、Chicago、Harvard、Vancouver）：references/citation-style.md。

## 输出语言

优先遵循显式语言要求。如果目标是中文期刊或中文论文，写中文学术正文；否则默认英文。绝不从用户输入语言推断输出语言：用中文描述想法但投稿英文是常态。

## 与兄弟技能的边界

- `intro-drafter`：Introduction 正文（本技能将 STEM Introduction 路由到那里）。
- `paper-polish`：润色已有正文，含中文转英文。
- `tech-paper-template`：写作前的逻辑骨架。
- `benchmark-paper-template`：规划 Benchmark 论文。
- `pre-submission-reviewer`：完成稿的审稿人式审计。
- `idea-evaluator`：想法是否值得追求。

如果起草揭示问题不是"怎么写"而是"核心声称是否成立"，在交付备注中如实说明，指向 `pre-submission-reviewer` 或 `idea-evaluator`。绝不为核心声称写辩护来掩盖用户自己的数据所削弱的东西。
