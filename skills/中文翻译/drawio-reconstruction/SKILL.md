# Draw.io 重建

本技能用于将图表图像高质量重建为 `.drawio` 文件。

## 辅助脚本位置

运行任何捆绑辅助工具之前，将 `SKILL_DIR` 解析为包含此 `SKILL.md` 的绝对目录。使用运行时提供的已解析技能位置；绝不假设技能安装在 `~/.codex`、`~/.agents` 或任何其他固定目录下。

下文所有命令中的 `$SKILL_DIR` 指该已解析的绝对目录。

## 保真合同

首要目标是对参考图像的视觉保真。可编辑性是次要的。

不要将语义等价视为成功。通用图标、通用曲线、通用字号、近似面板、近似背景在参考图有特定视觉风格时都是缺陷。

脚本检查只能证明技术有效性。一个图表不仅因为 `.drawio` 能打开、能导出或通过 `check_drawio.py` / `batch_verify.py` 就算完成。完成要求与参考图全尺寸视觉比较。

仅在用户指定的目标目录或目标文件中工作。不要因为看起来相关就去修复、覆盖或改进邻近图表。如果请求的目标不明确，先检查并报告歧义再编辑。

绝不默默重写用户内容。如果用户要求更大字体或更专业的 PPT 风格，先区分：

- **仅布局精修**：增大字号、调整框大小、改善间距、对齐元素、调整换行，不改文字。
- **内容压缩**：缩短句子、删除细节、重写标签。做之前须征得同意。

## 批量文件夹工作流

当用户提供图像目录或要求批量重建时使用此工作流。

### 批量意图与调度

在对图像进行详细视觉分析之前，先判断请求是否为批量重建任务：

- 当请求命名了文件夹、多个图像文件、通配符/模式或解析为 **2 张或以上图像条目**的任何目标时，视为批量重建。
- 在详细的逐图工作开始之前创建并审查清单。
- 当子代理工具可用且有用时，使用不超过可用并发和待处理图像数量的有界工作池。给每个活跃工作器恰好一张图像和该图像 `.drawio`、导出 `.png`、审计文件及私有资产/裁剪目录的独占写入集。将空闲槽位复用于下一张图像，而非试图同时启动所有工作器。
- 当子代理工具不可用、被禁用、受容量限制或小批量不需要时，按清单顺序串行处理条目。保持相同的盘点、重建、导出、检查和视觉审计要求。
- 仅在调度限制实质影响时间或交付时告知用户。不要仅因并行执行不可用就阻止有效批量任务。
- 协调代理可在选择调度前检查缩略图或文件元数据以确认范围、命名、方向和共享风格约束。

1. 确定输入目录、输出目录、命名约定和覆盖策略。
2. 创建批量清单：

   ```bash
   python "$SKILL_DIR/scripts/batch_manifest.py" path/to/images --output-dir path/to/output --write
   ```

3. 编辑前审查清单。仅处理清单中的条目，除非用户扩展范围。
4. 为每张图像在目标输出目录中定义预期的 `<stem>.drawio`、`<stem>.png` 和轻量 `<stem>.audit.md` 输出。
5. 选择有界并行调度或串行调度：
   - 为每个活跃条目分配独占输出文件。
   - 告知工作器代码库中不只有它们，不得回退或编辑其他工作器的输出。
   - 要求每个条目遵循与独立单图任务相同的完整工作流。批量模式仅是调度策略；不降低保真、盘点、重建、导出、检查或视觉审计要求。
   - 对每个条目应用此质量门：产出 `.drawio`、`.png` 和 `<stem>.audit.md`；创建完整的可见元素盘点；分类非文本视觉；按正常媒介规则使用裁剪/SVG/原生元素；运行所需检查/导出；将导出预览与参考图视觉比较；标记未解决的视觉缺陷而非声称完成。
   - 将最终批量验证、视觉检查、审计审查和面向用户的完成报告保留在协调代理处。
6. 重建后运行批量验证：

   ```bash
   python "$SKILL_DIR/scripts/batch_verify.py" path/to/output/drawio_batch_manifest.json
   ```

7. 打开每个导出预览并与参考图比较。不要仅信任工作器完成或脚本成功。
8. 报告已完成、跳过、失败的条目以及需要审查的图像。

默认批量输出：

- `drawio_batch_manifest.json`
- `<image-stem>.drawio`
- `<image-stem>.png`
- `<image-stem>.audit.md`

除非用户明确要求，不覆盖已有输出。如果输出已存在，跳过或创建明确命名的修订如 `<stem>-v2.drawio`。

## 强制参考盘点

重建每张图像之前，创建可见元素盘点。对复杂或批量工作，写入 `<stem>.audit.md`；对很小的单图，在工作笔记中维护但仍执行相同检查。

盘点必须覆盖每个可见区域和元素：

- 画布尺寸、背景、网格、纹理、渐变、阴影、页面边界
- 标题、副标题、章节标题、页脚、页码
- 面板、卡片、容器、分隔线、徽章、编号标记
- 每个文本块和标签
- 每个图标、插图、截图、Logo、图表、缩略图或装饰性视觉元素
- 每个箭头、曲线、连接器、环、括号、虚线路径和箭头头
- 定义布局的所有间距关系

每个盘点项必须包含：

- `id`
- 近似区域或边界框
- 内容 / 视觉描述
- 所选媒介：原生 / SVG / 裁剪 / 生成清理
- 风格备注：颜色、描边、字体、大小、阴影、曲线几何、内边距
- 状态：待处理 / 完成 / 需修复 / 已接受

在所有可见盘点项被接受或明确报告为未解决之前，不开始最终交付。

## 重建策略

为视觉保真使用最佳媒介。不要全局将所有非文本视觉默认为截图，也不要全局将所有视觉重绘为 SVG。决定性问题是：哪种方法在导出后最匹配参考图？

对以下情况优先使用 **Draw.io 原生元素**：

- 可编辑文本、标题、标签、芯片、标注
- 框、面板、分隔线、简单表格、简单图表、徽章
- 原生几何能匹配参考图时的结构性箭头/连接器
- 应保持易于编辑的重复布局结构

对以下情况默认使用 **PNG 裁剪 / 截图**：

- 复杂图标、详细符号、装饰性插图和混合对象视觉
- 通用 SVG 无法匹配参考图风格的风格特定图标族
- 视觉隐喻和场景类插图：冰山、人物、环境、仪表板、显示器、实验室场景、房间、风景、工作流场景
- 真实 UI 截图、手机/仪表板条、应用缩略图、证据截图、密集微型图表
- 人物、卡通角色、表情面孔、手、肢体姿势或人机交互场景
- 精确视觉保真比可编辑性更重要的情况
- 任何需要大量路径、渐变、蒙版或手动近似才能重绘的非文本视觉
- 任何 SVG/原生尝试会简化、省略或明显扭曲重要细节的视觉元素

对以下情况仅使用 **SVG/原生**：

- 参考图形状和风格可匹配的简单干净图标，不仅是语义上的命名匹配
- 具有简单轮廓/填充几何、1-2 种主色、无必要纹理、无密集内部细节且可重现清晰参考风格的图标
- SVG 可保持与参考图相同描边宽度、比例、颜色和缩放的重复简单图标族
- 裁剪会模糊或背景污染且形状级 SVG 匹配可行的小型源图标
- 用户明确需要矢量可编辑性的元素

不要仅因语义标签匹配就使用通用标准图标。数据库、图表、文档、靶心、大脑、机器人、手机、剪贴板、光标、灯泡、分子、烧杯、显示器等类似图标仍须与参考图做形状/风格检查。

## 媒介决策规则

重建每个视觉元素之前先分类。

1. 如果是文本或结构，使用 Draw.io 原生元素。
2. 如果是具有独特参考风格、密集细节、渐变、阴影、多对象组合或场景/隐喻内容的视觉元素，裁剪它，除非用户明确要求矢量可编辑性。
3. 如果是简单干净图标，仅当 SVG 能匹配参考图的形状、描边、比例、填充和视觉族时才使用 SVG/原生。
4. 如果 SVG 语义正确但视觉上通用，不使用。裁剪参考图或创建更接近的形状级 SVG。
5. 如果裁剪模糊、污染或有可见矩形，先修复裁剪/背景。仅在视觉简单且 SVG 匹配比裁剪更接近参考图时切换为 SVG。
6. 如果裁剪背景接缝可见，尝试透明 PNG 清理或将裁剪背景匹配到包含面板。
7. 如果常规清理留下光晕、锯齿边缘、水印、JPEG 块或不匹配面板，将裁剪放在同色背景块上、更紧地裁剪或使用可用的图像编辑/生成工具仅修复背景。
8. 如果裁剪和 SVG/原生都不可接受，在审计中将该项标记为 `needs-fix` 而非默默替换为差图。

阻塞性媒介缺陷：

- 参考图有风格特定图标但使用了通用替代图标
- 复杂视觉被重绘为简化 SVG 且无用户要求的矢量可编辑性理由
- 简单图标有清晰裁剪可用却使用了模糊裁剪
- 裁剪的复杂插图有可见背景接缝、光晕、缺失描边、裁剪阴影或无关邻近文本/边框
- 缺失突出图标、装饰标记或详细视觉

## 图标重建纪律

编写图标 SVG 或嵌入裁剪之前，从参考图制作角色到符号的映射。例如：

- 规划：大脑、清单、规划符号
- 工具使用：扳手、交叉工具、终端、工具符号
- 记忆：数据库圆柱、存储、记忆符号
- 验证：盾牌、勾号、审计、验证符号
- 证据卡片：模式/表、日志/文档、执行树/计划、指标/仪表

对每个映射条目：

- 对复杂、风格特定或详细符号使用源图像裁剪。
- 仅对可匹配参考图风格的简单干净图标使用独立 SVG 或原生 Draw.io 符号。
- 保持描边宽度、颜色、比例和大小与参考图一致，而非与通用图标集一致。
- 不要复制一个图标仅改变位置或标签。
- 除非参考图本身使用相同重复占位符，否则不使用通用占位图标。
- 如果符号不简单干净，从参考图裁剪该特定符号而非替换为无关 SVG。

创建或编辑图标后运行 `check_drawio.py`。证据图标、核心条图标、工作流步骤图标或结果行图标中的重复图像载荷是阻塞性失败，除非参考图有意重复同一符号。

## 截图裁剪规则

以下情况使用截图/PNG 裁剪：

- 插图太复杂无法高效重绘
- 精确视觉风格比可编辑性更重要
- SVG 尝试仍看起来差或通用
- 用户提供或批准了好的裁剪
- 视觉是复杂图标其细节在手绘 SVG 中会丢失
- 视觉是真实 UI 截图、手机条、仪表板缩略图、密集证据制品、人物、场景或视觉隐喻

使用截图时：

- 避免对可编辑文本或结构布局使用截图。
- 围绕目标前景插图裁剪，而非整个周围区域。
- 从粗略 ROI 开始，识别前景边界框，然后添加适度安全内边距。
- 尽可能使用裁剪辅助工具：

  ```bash
  python "$SKILL_DIR/scripts/crop_assist.py" reference.png --roi x,y,w,h --anchor x,y --exclude x,y,w,h --output-dir crops --name icon_name
  ```

- 在嵌入裁剪之前视觉检查生成的预览和候选项。脚本提议边界；模型仍决定哪个候选项最匹配参考图。
- `crop_assist.py` 需要 Pillow。如果 Pillow 不可用，在更改环境之前请求批准，然后用 `python -m pip install -r "$SKILL_DIR/requirements.txt"` 安装捆绑的可选依赖。不要默默跳过裁剪检查。
- 对粗略 ROI 内但不属于目标插图的邻近元素使用 `--exclude` 框，特别是项目符号、正文、标题线、编号徽章、面板边框和分隔线。
- 安全内边距应保留完整描边、箭头头、阴影、抗锯齿和即时有意留白。不应扩展到一般空白区域。
- 除非为避免邻近内容需要紧裁剪，否则不要紧贴可见描边裁剪。裁剪描边、切掉箭头头、缺失阴影或插图触及裁剪边缘是阻塞性缺陷。
- 不要包含邻近项目符号、标签、标题线、卡片边框、分隔线或无关同色标记。如果更多内边距会拉入邻近内容，使用更紧的有效候选项并通过透明或颜色匹配处理背景。
- 当周围面板/背景不均匀时优先使用透明 PNG。
- 如果透明不可能或清理产生光晕，将裁剪放在同色背景块上。
- 如果裁剪背景颜色与 Draw.io 面板不匹配，更紧裁剪、移除背景、重新着色/匹配裁剪背景或设置包含面板/背景以匹配。
- 如果裁剪复杂且常规清理后仍有背景不匹配，使用可用的图像编辑/生成工具仅修复或中和背景；不改动语义前景。
- 检查导出 PNG 的可见接缝、抗锯齿光晕、锯齿透明、模糊或不匹配背景。不留可见矩形裁剪接缝。

## 曲线与箭头

对每个箭头或曲线，在选择实现之前匹配参考图。

创建箭头盘点：

- 源元素和目标元素
- 起点/终点锚点
- 方向
- 线型：实线、虚线、点线、曲线、垂直、水平、环
- 描边宽度、颜色、箭头头类型和大小
- 弯折点、拐角半径以及路径在面板前还是后
- 语义角色：工作流转换、反馈环、证据支撑、标注、装饰提示

实现顺序：

1. 原生 Draw.io 连接器用于结构性连接器（当它们能匹配参考图时）。
2. SVG 路径用于特殊花括号、曲线箭头、环形箭头、圆角返回路径或原生 Draw.io 无法匹配的装饰箭头。
3. PNG 裁剪仅用于高度特定的不可编辑装饰标记。

大环形箭头、虚线反馈曲线和圆角返回路径必须匹配参考图路径几何。不要用近似通用连接器替代。

## 排版与布局

在分配大小之前从参考图提取排版：

- 主标题
- 副标题
- 章节标题
- 卡片标题
- 卡片正文
- 标签/芯片
- 页脚/页码
- 图标-标签对

对每个文本角色，捕获近似字号、字重、颜色、行高、对齐方式和可用框大小。除非参考图明确是 SIGMOD 风格运行示例，否则不应用 SIGMOD 运行示例字号基线。

将每个文本变化视为盒模型变化：

`文本 -> 文本框 -> 卡片/行 -> 包含面板 -> 邻近布局`。

硬性失败：

- 文本视觉上变大但背景卡片/面板未调整大小
- 文本框高度小于渲染文本高度
- 文本触及边框、与图标重叠或超出行/卡片
- 参考图中有空间时出现不存在的尴尬换行
- 父卡片容纳文本但不再适合面板内
- 页脚或幻灯片边界被推入内容区

## 默认工作流

1. 确定参考图像和目标输出目录。
2. 处理文件夹或多张图像时创建或更新批量清单。
3. 为每张图像创建参考盘点和风格令牌笔记。
4. 尽可能使用 Draw.io 原生元素重建文本和结构。
5. 用媒介决策规则分类每个非文本视觉。
6. 对复杂/风格特定视觉使用源图像裁剪或透明 PNG；对通过形状/风格匹配的简单干净图标使用 SVG/原生。
7. 用 Draw.io CLI 导出 PNG 预览。
8. 运行检查器。将任何布局失败视为阻塞性缺陷，不是警告。
9. 与参考图全尺寸逐项视觉审计。
10. 迭代布局、大小、对齐、字号、裁剪、图标和箭头直到技术检查和视觉审计都通过。
11. 报告已更改文件和剩余质量风险。

默认输出：

- `<name>.drawio`
- `<name>.png`
- `<name>.audit.md`（批量或复杂重建）

## 强制视觉审计

最终响应之前，将导出 PNG 与参考图全尺寸比较，逐项检查每个盘点项。

阻塞性缺陷：

- 缺失可见元素
- 通用替代图标
- 错误的图标/插图风格、描边、缩放或内部细节
- 错误的曲线、环、虚线路径、箭头路由、箭头头或连接器层级
- 错误的标题/正文字号、字重、换行、颜色或对齐
- 文本重叠、裁剪、触及边框或参考图中不存在的尴尬换行
- 错误的面板/卡片大小、圆角、阴影、边框或间距
- 背景不匹配、缺失渐变/网格/纹理或错误的页面边界
- 裁剪接缝、模糊、光晕、透明不良、错误裁剪边界或裁剪内含邻近内容
- 仅脚本通过而无参考比较
- 任何盘点项仍标记为 `needs-fix`

任何项失败则继续编辑。不要将图表呈现为已完成。

对批量任务，父代理必须在最终响应前打开每个导出预览和每个工作器审计文件。工作器完成不等于交付验收。

## 使用用户批准的参考图

如果用户提供手动调整的截图或 `.drawio` 文件作为质量参考，在更改另一图表之前将其作为风格来源。

有 `.drawio` 文件时优先使用，因为它暴露真实几何：

- 按语义角色提取字号。
- 提取几何比例：卡片宽/高、标题/正文文本框高度、图标大小、角色标签高度、证据面板高度、结果行高度和内边距。
- 在主观视觉调整之前将这些基于角色的值应用到目标图表。
