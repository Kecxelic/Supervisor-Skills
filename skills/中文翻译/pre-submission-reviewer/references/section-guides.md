# 各章节写作指南

## 目录

1. 摘要
2. Introduction
3. 问题形式化
4. 框架或方法论
5. 实验
6. Related Work
7. 结论

## 1. 摘要

五句公式。

| 句 | 内容 |
|---|---|
| 1 | 论文解决什么问题？上下文加重要性 |
| 2 | 为什么值得解决？没人做过，或已有方法失败 |
| 3 | 挑战是什么？必须具体；问题的挑战非方法的 |
| 4 | 问题如何解决？方法名和关键组件，匹配挑战 |
| 5 | 方法表现如何？真实数据集、具体数字、代码链接（如有） |

常见失败：

- 什么和为什么太抽象。
- 缺挑战句。
- 结果句无具体数字。
- 首句有炒作词（revolutionary、groundbreaking）；读起来像防御。

## 2. Introduction

六段公式匹配 Introduction 流程图。

| 段 | 内容 |
|---|---|
| 1 | 问题；具体动机示例 |
| 2 | 已有方法及其局限；高度浓缩，至多三条局限 |
| 3 | 问题本质和硬约束；论文目标或关键想法 |
| 4 | 关键挑战；问题的挑战非方法的 |
| 5 | 方案概述；与挑战一一对应 |
| 6 | 贡献摘要，三到四条，各映射到章节 |

关键约束：

- 吸引审稿人。基本决定录用。
- 突出新颖性和技术深度。
- 明确陈述与已有工作的差异。
- 写论文自己的想法；其他工作属于 Related Work。
- 术语精确；读者应快速把握论文核心。

## 3. 问题形式化

三步：

1. 用正文描述问题使读者理解范围。
2. 用记号和公式呈现正式定义。
3. 用具体示例锚定理解。

关键约束：一篇论文应解决一个问题，而非多个。强运行示例比额外形式化机制更有价值。

## 4. 框架或方法论

组织原则：从总到细。节以架构开始然后钻入组件；每个组件的子节重复此模式。

| 部分 | 内容 |
|---|---|
| 架构概述 | 全局图；读完此部分读者在高层理解技术 |
| 工作流走查 | 端到端追踪输入通过系统 |
| 简单组件 | 在框架节内联描述 |
| 复杂组件 | 此处高层覆盖；完整细节推迟到专用子节或节 |

必须有：

- 新颖性和贡献明确陈述。
- 总体架构图。
- 如某组件无新颖性，最小化覆盖；已知技术的长描述增加噪声。
- 后续子节按新颖性排序：最强在前。
- 自包含；插图丰富；每子节有引导文本。

避免：

- 详细解释为何拒绝替代方法；那属于 Related Work 或消融。
- 已有工作记号片段与论文记号混合。
- 子节间符号漂移；定义一次一致使用。

## 5. 实验

时态：过去。

设置要求：

- 先陈述实验目标。
- 至少三个数据集。
- 评估指标命名并论证。
- 基线仔细选择；明显基线不可遗漏。如论文引用证明 A 胜过 B 和 C 的工作，仅需 A，附说明。

总体比较：

- 先对所有基线的端到端比较。
- 先陈述指标再分析结果。
- 陈述提升，解释原因，提取发现。

消融研究：

- 评估每个拟议组件的贡献。
- 对三个组件 A、B、C：报告 All、-A、-B、-C。
- 变化关键超参数。

必须有：

- 真实数据集和有说服力的基线。
- 结论明确陈述。实验展示了什么？为什么？

## 6. Related Work

位置：

- 第 2 节如论文依赖已有框架、模型或方法来理解。
- 倒数第二节如论文自包含。倒数第二位置是强论文的偏好默认。

要做：

- 用作者自己的话总结。不复制句子。
- 公平归功；不过度批评。
- 聚焦高层摘要，非次要细节。
- 自包含；解释论文与相关工作的差异。
- 按方法类别分组，然后陈述差异。直接批评最近相关工作；较远相关工作获较少批评和较多确认。
- 引用使用会议缩写（SIGMOD、VLDB、ICDE、TKDE）。从 DBLP 拉 bibtex。

不要做：

- 从相关工作复制句子，绝不。剽窃是红线。

## 7. 结论

时态：现在完成时（we have shown, we have proposed）。

目的：总结贡献和意义。不重复 Introduction。

- Introduction 面向尚未读论文的读者。
- 结论面向已读完论文的读者；他们知道技术细节。

以一到两句含义或未来方向收尾。避免关于"影响"的模糊声称。
