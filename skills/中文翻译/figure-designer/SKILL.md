# 图表设计器

## 概述

顶会论文通常有六到八张图，其中三张几乎承载了全部叙事重量：Motivated Example（Figure 1，在第 1 页或第 2 页顶部）、Solution Overview（方法论章节内）和实验结果图（实验章节内）。审稿人在一分钟内扫完这三张图来决定论文是否值得细读；弱图会让本来很强的论文沉没。

本技能接受用户的意图（想传达什么）加上上下文（研究领域、方法名、目标会议），返回推荐范式、布局草图、标注指导、工具建议，以及对照通用规则集（矢量格式、字号、色盲安全编码、自包含标题、诚实坐标轴范围）的质量控制审计。

## 何时使用本技能

- 在论文中绘制任何图之前。
- 用户要求"设计图表"、"画 Figure 1"、"绘制实验结果"、"选择图表类型"。
- 用户已画好图，想要设计审计。
- 用户不确定选哪种图类型或范式。
- 投稿前准备终版图。

## 何时不用本技能

- 用户只是想要论文之外的通用绘图帮助（柱状图、折线图）。常规帮助足矣。
- 论文尚未结构化；先用 `intro-drafter` 或 `tech-paper-template` 确定需要哪些图。
- 用户想要对已完成的论文做审查。使用 `pre-submission-reviewer`。

## 核心流程

### 步骤 1：图类型识别

判断该图属于三种核心类型中的哪一种。如果用户的请求不匹配任何一种，要么是辅助图（以实验结果指南为基准），要么不该出现在论文中。

如果模式为 `figure-audit` 且用户提供了图片路径，在进入步骤 2 **之前**用 Read 工具加载图片。基于视觉的检查使步骤 6 的通用规则审计能直接检查字体可读性、配色方案、位图 vs 矢量特征和图表噪音，而非依赖用户描述。如果未提供图片，继续纯文本模式，将仅视觉可检查的规则（字号、位图检测、配色方案）在最终审计报告中标记为"用户须验证"。

### 步骤 2：范式推荐

参见：references/motivated-example.md、references/solution-overview.md 或 references/experimental-results.md，取决于图类型。

每种图类型有两到三种标准范式。选择最适合用户叙事需求的一种，并解释其他范式为何不太合适。

### 步骤 3：布局草图

产出布局的文字描述：面板位置、元素放置、箭头、配色分配。目标是用户仅凭草图就能画出初稿。

### 步骤 4：标注与注释指导

- 每个可见元素都给具体名字（不用"模块 A"、"X"、"Y"）。
- 标注关键点（失败高亮、成功高亮、对比强调）。
- 明确字号和配色方案。默认配色方案：ColorBrewer 定性色板或 Viridis 连续色板。

### 步骤 5：工具建议

参见：references/tools.md 了解工具矩阵和决策启发式。

默认推荐：

- Motivated Example 和 Solution Overview：PowerPoint（起草）、Figma（精修）。
- 实验结果：Matplotlib 或 Seaborn，写在可复用的 `plot_utils.py` 脚本中。
- LaTeX 集成图：TikZ 或 PGFPlots。

### 步骤 6：通用规则审计

参见：references/design-rules.md 了解完整通用规则集。

对每个提议或现有的图验证：

- 矢量格式（PDF、EPS、SVG）导出。
- 缩放后字号至少 8pt。
- 小画布（不是大画布配小字）。
- 色盲安全色板；不仅靠颜色编码。
- 自包含标题，首句陈述核心发现。
- 诚实的坐标轴范围。
- 无 3D 效果，无图表噪音。

对每个违规标记严重性。

### 步骤 7：完整性门禁

运行下方完整性门禁部分的检查。

### 步骤 8：输出

按下方输出格式输出完整设计。

## 完整性门禁

标记为 [inspection] 的项由 LLM 从自身输出检查。标记为 [user-verify] 的项需要用户确认，因为检查依赖于已绘制的图或技能不具备的知识（论文上下文、已有 Introduction）。

返回设计之前：

1. **[inspection]** 范式匹配图类型（motivated example 不是管线图；overview 不是柱状图）。
2. **[inspection]** 布局草图足够具体，用户可据此绘制。
3. **[inspection]** 标注为真实实体名，非占位符。
4. **[inspection]** 工具建议匹配图的复杂度（多图标 motivated example 不用 Matplotlib；20 方法柱状图不用 PowerPoint）。
5. **[inspection]（提供图片时），[user-verify]（纯文本时）** 通用规则审计已运行；无未处理的 CRITICAL 违规。仅视觉规则（位图 vs 矢量、字号、配色方案）仅在用户提供图片时可检查。
6. **[user-verify]** 对 motivated example，该示例是 Introduction 引用的同一运行示例（Figure 1 中不引入新示例）。技能看不到 Introduction；用户确认。
7. **[inspection]** 对实验结果，图表类型匹配数据类型（时间序列用折线图，多方法比较用分组柱状图，权衡用散点图）。

任何 [inspection] 检查失败，将设计标记为"需用户关注"。对 [user-verify] 项，将其呈现给用户，要求在投稿前确认。

## 输出格式

### 1. 图类型
- 类型：<motivated-example 或 solution-overview 或 experimental-results>
- 原因：<一句话>

### 2. 范式推荐
- 范式：<名称>
- 为何选此范式：<理由>
- 考虑并否决的替代方案：<列表>

### 3. 布局草图
- 画布：<尺寸>
- 面板：<列表，含位置和内容>
- 箭头与连接：<列表>
- 配色分配：<映射>

### 4. 标注与注释
- 元素名称：<列表>
- 关键高亮：<列表>
- 字号：<目标>
- 配色方案：<名称>

### 5. 工具建议
- 首选：<工具>
- 备选：<工具>
- 原因：<理由>

### 6. 通用规则审计
- [ ] 矢量格式：<通过或未通过>
- [ ] 字号：<通过或未通过>
- [ ] 色盲安全：<通过或未通过>
- [ ] 自包含标题：<通过或未通过>
- [ ] 诚实坐标轴范围（如适用）：<通过或未通过>
- [ ] 无图表噪音：<通过或未通过>

### 7. 完整性门禁结果
- 门禁 1-7：<通过或未通过>

### 8. 严重性汇总
- <n> CRITICAL，<m> MAJOR，<k> MINOR
- 前三项行动：...
