## 2. 示例 A：Alpha-SQL，技术类

### 论文类型定位

技术论文。Text-to-SQL 已确立；贡献是新的推理时机制（MCTS 搜索）。

### 填好的模板

| 阶段 | 内容 |
|---|---|
| 研究背景 | 企业分析的 Text-to-SQL。分析师不懂 SQL 的生产使用。近期工作：OpenAI Codex、DIN-SQL、DailySQL |
| 局限 1 | 单遍提示在复杂多表 JOIN 查询上失败 |
| 局限 2 | 每个模式微调昂贵且不泛化 |
| 关键想法 | 在推理时使用蒙特卡洛树搜索探索 SQL 候选并通过执行反馈评分 |
| 挑战 1 | SQL 候选空间组合爆炸；朴素搜索不可行 |
| 挑战 2 | 无训练批评者可用于推理时奖励 |
| 方法论主题句 | Alpha-SQL 结合 SQL 解析树上的结构化 MCTS 搜索和来自执行反馈的自监督奖励 |
| 模块 A（挑战 1） | MCTS 引导的 SQL 生成，带学习扩展先验 |
| 模块 B（挑战 2） | 通过基于执行的验证的自监督奖励 |
| 贡献 1 | MCTS Text-to-SQL 推理框架（第 3 节） |
| 贡献 2 | 自监督奖励设计（第 4 节） |
| 贡献 3 | 在 BIRD 和 Spider 上的实验，N 点提升（第 5 节） |

### 一致性检查
- 检查 1（局限 -> 关键想法）：通过。两条局限均由推理时 MCTS 回应。
- 检查 2（关键想法 -> 挑战）：通过。两条挑战均从 MCTS 产生。
- 检查 3（挑战 -> 方法论）：通过。一一对应。
- 检查 4（方法论 -> 贡献）：通过。

## 3. 示例 B：AFlow，带跨领域框架的技术类

### 论文类型定位

技术论文，混合跨领域。算子图搜索从 NAS 移植到代理工作流。

### 填好的模板

| 阶段 | 内容 |
|---|---|
| 研究背景 | 代码生成 LLM 代理；HumanEval 和 MBPP benchmark；近期代理工作流工作 |
| 局限 1 | 仅提示工程产出脆弱工作流 |
| 局限 2 | 单代理架构不捕获算子组合 |
| 局限 3 | 手工设计工作流不跨任务家族泛化 |
| 关键想法 | 将代理工作流设计框架化为算子图上的搜索，借用自神经架构搜索 |
| 挑战 1 | 算子图搜索空间组合爆炸 |
| 挑战 2 | 工作流的奖励信号离散且稀疏 |
| 方法论主题句 | AFlow 结合执行奖励引导的算子图搜索 |
| 模块 A（挑战 1） | 带学习先验的算子图搜索 |
| 模块 B（挑战 2） | 通过代码执行的结构化奖励 |
| 贡献 1 | 将工作流设计框架化为算子图搜索（第 2 节） |
| 贡献 2 | AFlow 搜索算法（第 3 节） |
| 贡献 3 | 在 HumanEval、MBPP 上的实验，对手工工作流一致提升（第 4 节） |

### 一致性检查
- 全部四项通过。
- 跨领域框架反映在贡献 1 中。

## 4. 示例 C：LEAD，新问题/设定类

### 论文类型定位

新问题/设定论文。目标承载叙事。

### 填好的模板

| 阶段 | 内容 |
|---|---|
| 研究背景 | LLM 指令微调；数据质量胜过数量；近期迭代数据选择工作 |
| 局限 1 | 非迭代选择不适应模型演化 |
| 局限 2 | 迭代方法每轮需昂贵的全数据集推理 |
| 关键想法/目标 | （目标）无任何额外推理开销的迭代数据选择。（关键想法）用微调环中已计算的训练损失作为零开销效用信号 |
| 挑战 1 | 从噪声训练损失轨迹中提取可靠效用信号 |
| 挑战 2 | 将选择信号集成到训练环中不扰动收敛 |
| 方法论主题句 | LEAD 使用实例级动态不确定性作为效用信号，并将选择延迟到保持收敛的节奏 |
| 模块 A（挑战 1） | 实例级动态不确定性信号，带统计去噪 |
| 模块 B（挑战 2） | 延迟选择集成到微调环中 |
| 贡献 1 | 问题形式化：无额外推理的迭代数据选择（第 2 节） |
| 贡献 2 | 实例级动态不确定性及理论分析（第 3、4 节） |
| 贡献 3 | LEAD 框架设计（第 3 节） |
| 贡献 4 | 大量实验（第 5 节） |

### 一致性检查
- 全部四项通过。
- 贡献 1 直接编码目标。

## 5. 跨示例观察

- 三个示例都使用 2 或 3 条局限、2 个挑战、2 个方法论模块。这些计数的一致性非偶然。
- 三个示例都通过四项一致性检查。这是强顶会投稿的最低标准。
- 新问题/设定示例（LEAD）有四条贡献因为问题形式化占一个贡献位，剩三个给方法和实验。
- 混合情况（AFlow）以跨领域框架在贡献 1 中引领。这是跨领域技术论文的经典模式。
- 三个示例无一包含模糊贡献。每条贡献都具体且映射到章节。
