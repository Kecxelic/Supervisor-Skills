## 1. 三种论文类型

顶会（SIGMOD、VLDB、ICML、NeurIPS、ICLR、ACL）技术论文分三类。正确定位是第一个规划决策。

- **技术论文**：已有问题上的新方法或机制。关键想法承载叙事。
- **新问题/设定论文**：新问题形式化或已有问题中的新设定。目标或问题形式化承载叙事。
- **跨领域技术论文**：贡献将一个领域的想法移植到另一个的技术论文。关键想法承载叙事但 `idea-evaluator` 框架的更广维度在 Introduction 中被强调。

Benchmark 论文是独立类别；使用 `benchmark-paper-template`（单独插件）。

## 2. 技术论文

信号：

- 问题已确立。已有命名 benchmark；已有工作丰富。
- 贡献是"we do X better"。
- 审稿人在同一问题上与最强已有方法比较。
- 实验聚焦于在共享指标上超越基线。

模板含义：

- 关键想法单元格承重。
- 目标是短桥，非贡献。
- 挑战从实现关键想法中流出。
- 贡献 1 通常是框架或方法名。

## 3. 新问题/设定论文

信号：

- 问题是社区尚未如此研究的新框架。
- 相邻问题已有工作但非此特定框架。
- 贡献是思考空间的新方式，非已有问题上的新方法。
- 实验刻画新问题而非超越排行榜。

模板含义：

- 目标单元格承重。可能需要多句。
- 关键想法支撑"为何此定义合理且可行"。
- 局限段落展示为何已有框架遗漏此问题。
- 贡献 1 是问题形式化本身。

## 4. 混合情况：跨领域技术

将成熟想法从一个领域移植到另一个的论文是带更广维度框架的技术论文。

信号：

- 技术在一个子领域成熟但对另一个新。
- Introduction 依赖"inspired by X from field A, we apply it to field B"。
- 贡献是迁移和机制，非从头发明的技术。

模板含义：

- 关键想法包含源领域技术和迁移机制。
- 局限强调领域 B 在领域 A 文献中的缺席。
- 挑战通常包括"跨领域差距迁移想法 X"。
- 贡献 1 命名迁移。

示例：AFlow（ICLR 2025）将算子图搜索（来自神经架构搜索）移植到代理工作流设计。

## 5. 定位问题

按顺序询问。首个"是"决定：

1. 论文主要贡献是 benchmark 吗？如是，停止并重定向到 `benchmark-paper-template`（单独插件）。
2. 论文主要贡献是社区尚未研究的新问题形式化吗？如是，新问题/设定。
3. 论文主要贡献是从另一领域移植的技术吗？如是，混合（带跨领域框架的技术）。
4. 默认：技术论文。

如用户答案与此顺序冲突，调查。论文可合理地有两种强框架；见 Introduction 起草器技能的 paper-types 参考中的混合情况讨论。

## 6. 定位如何影响模板

| 单元格 | 技术 | 新问题/设定 | 混合跨领域 |
|---|---|---|---|
| 背景 | 展示问题的场景 | 展示现象的场景 | 展示两个领域的场景 |
| 局限 | 针对已有方法 | 针对已有框架 | 针对领域 B 在领域 A 中的缺席 |
| 关键想法/目标 | 关键想法句主导 | 目标句主导，常多句 | 关键想法命名迁移 |
| 挑战 | 从实现关键想法推导 | 从实现新设定推导 | 从领域差距推导 |
| 方法论 | 实现关键想法的模块 | 实现设定的模块 | 实现迁移的模块 |
| 贡献 | C1 = 框架或方法；C2-C4 = 技术、评估 | C1 = 问题形式化；C2-C4 = 框架、技术、评估 | C1 = 迁移框架；C2-C4 = 方法、评估 |

在技能核心流程步骤 2 中填写模板时应用匹配定位的行。
