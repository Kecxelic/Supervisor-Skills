# 技术论文模板

## 概述

在起草任何正文之前，技术论文需要完整的逻辑骨架：研究背景、已有工作的具体局限、关键想法或研究目标、阻止朴素解决方案的技术挑战、回应每个挑战的方法论模块、以及论文将声称的贡献。本技能通过标准化的思考模板表格填写该骨架，定位论文类型，并对逻辑链运行四项自洽性检查。

输出是填好的思考模板加一致性报告。适用于导师-学生头脑风暴会议、周度进展汇报、以及写作开始前的最终规划步骤。它不起草 Introduction 正文（用 `intro-drafter`）；它在逻辑骨架层运作。

## 何时使用本技能

- 论文项目早期头脑风暴。
- 与导师或合作者的周度进展会议。
- `idea-evaluator` 返回强接受后的起草前规划。
- 论文逻辑链感觉不连贯，需要审计。
- 用户要求"论文骨架"、"论文逻辑链"、"思考模板"或"论文结构规划"。
- 用户不确定论文是技术类还是新问题/设定类。

## 何时不用本技能

- 论文是 Benchmark 论文。使用 `benchmark-paper-template`（单独插件）。
- 用户需要 Introduction 专门的段落大纲。使用 `intro-drafter`（通常先运行本技能，再 `intro-drafter`）。
- 用户已有书面草稿，想要审查反馈。使用 `pre-submission-reviewer`。
- 想法本身未经验证。先用 `idea-evaluator`。

## 核心流程

### 步骤 1：论文类型定位

定位标准和工作实例见：references/paper-types.md。

决定技术类 vs 新问题/设定类。技术类中，关键想法承载叙事，我们的目标是短桥。新问题/设定类中，我们的目标是贡献，关键想法证明可行性。

如果用户输入描述的是 Benchmark，停止并重定向到 `benchmark-paper-template`（单独插件）。

### 步骤 2：填写思考模板

各模板单元格的内容合同、强填写示例和常见失败模式见：references/thinking-template.md。

填写七个单元格：

1. 研究背景。场景、重要性、动机。
2. 局限 1 到 3（2 条可接受；超过 3 条不行）。
3. 关键想法或我们的目标。一句话。
4. 挑战 1 到 3（类似上限）。
5. 方法论模块。每个挑战一个模块。
6. 贡献（3 或 4 条，各映射到一个章节）。

如果给定用户输入某单元格不完整，标记为缺口并标严重性。

### 步骤 3：运行四项自洽性检查

详细检查程序和链条断裂示例见：references/consistency-checks.md。

逐项运行：

1. **局限到关键想法**：关键想法或目标是否回应了所陈述的局限？如果不是，要么局限错了，要么关键想法未对齐。
2. **关键想法到挑战**：挑战是否从实现关键想法中自然产生？如果不是，挑战是为模块编造的而非从想法推导的。
3. **挑战到方法论**：每个方法论模块是否回应一个挑战？如果不是，存在无理由的模块或无修复的挑战。
4. **方法论到贡献**：贡献是否覆盖每个模块或实验结果？如果不是，贡献模糊或承诺超出论文交付。

每个失败为 CRITICAL。

### 步骤 4：生成方法论大纲

方法论大纲模板见：references/thinking-template.md。

从挑战推导方法论大纲：主题句、各模块子节名、各模块一句话摘要。这成为论文第 3 或 4 节的骨架。

### 步骤 5：完整性门禁

输出之前，运行下方完整性门禁部分的检查。

### 步骤 6：输出

按下方输出格式输出填好的模板加一致性报告。

## 完整性门禁

七条均为 **[inspection]** 类：LLM 直接从填好的模板验证（计数、模式匹配或比较单元格）。无需用户侧确认。

返回填好的模板之前：

1. **[inspection]** 论文类型定位与用户实际贡献一致（技术论文不硬塞入新问题框架，反之亦然）。
2. **[inspection]** 局限具体且可引用，非模糊。
3. **[inspection]** 关键想法或目标是审稿人可引用的一句话。
4. **[inspection]** 挑战从实现关键想法中推导；非编造。
5. **[inspection]** 方法论模块与挑战一一对应。
6. **[inspection]** 贡献映射到方法论模块和具体章节。
7. **[inspection]** 四项自洽性检查全部通过。

任何检查失败，将骨架标记为"需用户关注"。

## 输出格式

### 1. 论文类型定位
- 类型：<技术论文 或 新问题/设定论文>
- 理由：<一句话>

### 2. 思考模板

| 阶段 | 你的内容 |
|---|---|
| 研究背景 | ... |
| 局限 1 | ... |
| 局限 2 | ... |
| 局限 3（如适用） | ... |
| 关键想法 / 我们的目标 | ... |
| 挑战 1 | ... |
| 挑战 2 | ... |
| 挑战 3（如适用） | ... |
| 方法论主题句 | ... |
| 模块 A（回应挑战 1） | ... |
| 模块 B（回应挑战 2） | ... |
| 模块 C（回应挑战 3） | ... |
| 贡献 1 | ...（第 <X> 节） |
| 贡献 2 | ...（第 <Y> 节） |
| 贡献 3 | ...（第 <Z> 节） |

### 3. 自洽性检查
- 检查 1 局限 -> 关键想法：<通过或失败>
- 检查 2 关键想法 -> 挑战：<通过或失败>
- 检查 3 挑战 -> 方法论：<通过或失败>
- 检查 4 方法论 -> 贡献：<通过或失败>

### 4. 严重性汇总
- <n> CRITICAL，<m> MAJOR，<k> MINOR。
- 前三项修复：...

### 5. 建议的下一步技能
- 如全部通过：用 `intro-drafter` 产出 Introduction 段落大纲。
- 如有失败：先修复标记的链条断裂。
