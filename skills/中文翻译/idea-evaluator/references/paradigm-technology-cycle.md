# 技术周期前瞻

## 1. 核心想法

颠覆式创新常与底层硬件或平台的代际转变重合。对此转变的错误反应是将旧算法移植到新硬件。正确反应是问转变使什么架构假设失效，然后从零为该假设不再成立的世界设计。

方法有两种工作技术：观察刚发生的转变，以及想象资源变为无限时会发生的转变。

## 2. 技术A：硬件或平台转变采纳

### 程序
1. 识别近 18 个月内触及子领域的两到三次技术转变。转变可以是硬件（GPU、NVM、RDMA）、软件（基础模型、Serverless）或成本曲线（推理成本、存储成本）。
2. 对每次转变，列出它改变的架构假设。
3. 对每个假设，问：子领域当前最佳方法是否仍依赖此假设？
4. 如是，当前方法该进行范式刷新。提出将转变视为新基线的重新设计。

### 转变是代际的信号
- 成本曲线变化一个数量级，非一个倍数。
- 出现此前不可能的新能力（不只是更多相同）。
- 生产部署开始在学术界发表之前采纳转变。
- 至少两个主要供应商或开源项目汇聚到新技术。

## 3. 技术B：无限资源思维实验

### 程序
1. 选一个具体资源：算力、内存、带宽、推理 token、标注预算。
2. 想象该资源变为 10000 倍便宜且零延迟。
3. 问：子领域的主导范式如何变化？
4. 寻找当前范式中仅因该资源昂贵才有意义的设计决策。
5. 提出将资源视为免费的重新构想。

### 此技术揭示什么
- 仅为节省现已丰富资源而存在的算法。
- 仅为压缩中间数据而存在的管线阶段。
- 仅因从原始输入学习过于昂贵而存在的精心工程特征。

经典先例：GPU 使丰富算力可用后深度学习的爆发。特征工程曾是核心，变为边缘。

## 4. 工作示例：非易失性内存数据库
- **转变**：字节可寻址非易失性内存（NVM）到来；存储现在是持久的且以近 DRAM 速度字节级可寻址。
- **移植方法（错误）**：在 NVM 上运行传统面向磁盘的数据库并做小幅调优。
- **第一性原理方法（正确）**：如存储是持久的且字节可寻址，数据库还需要缓冲池吗？还需要传统形式的预写日志吗？
- **重构**：为持久内存设计的新一代数据库，折叠基于页的 I/O 模型并重新思考崩溃恢复。

## 5. 工作示例：免费 token 大语言模型
- **思维实验**：假设 LLM token 零成本且上下文窗口无界。数据处理如何变化？
- **后果**：
  - 为将数据 fit 进有限上下文而存在的预处理管线变得不必要。
  - 微调变为可选；提示可以吸收微调数据集扮演的角色。
  - 检索系统变得更简单；模型可以直接读语料库。
  - 评估管线可以变为交互式而非批量。
- **重构**：统一的、提示优先的数据分析框架研究；代理驱动分析中代理阅读整个语料库。

## 6. 如何区分真实转变与炒作
- **真实转变**：成本曲线已实际移动；生产系统已部署新能力至少六个月；多个独立团队在探索。
- **炒作**：成本曲线仅在某供应商路线图幻灯片中移动；生产系统试过并回退；探索集中在单一研究组。
- **过早转变**：能力存在但规模仅超大实验室可获取。重构在纸面上有效但典型学生无机构支撑不可发表。记录在 Hamming 列表上。
- **过晚转变**：转变发生在三年或更早前且子领域已吸收。重构机会关闭；专注新范式内的增量提升。
