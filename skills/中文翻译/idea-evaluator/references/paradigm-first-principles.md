# 第一性原理思考

## 目录

1. 核心想法

3. 技术B：回到目的

## 1. 核心想法

不要从文献开始。从问题的物理或数学本质开始。已有解决方案继承了设计时刻的假设，那些假设可能已悄悄不再成立。第一性原理思考将问题剥离到本质上必需的，问从需求到当前解决方案的路径是否仍然成立。

技术看似简单：识别假设，测试是否仍成立，如不成立则提出不需要它的新方案。

## 2. 技术A：假设审计

### 程序
1. 写下子领域最广泛持有的三个假设。各以一句陈述句表述。
2. 对每个假设，写其最初理由（为何最初被采纳？）。
3. 对每个假设，问自该理由确立以来什么变了。
4. 按脆弱性排序假设。理由依赖不再成立条件的假设是候选。
5. 选最脆弱的假设，想象一个不做此假设的系统。什么成为可能？

### 好假设的样子
- 具体的。"Data distribution is static" 优于 "things are fixed"。
- 历史的。审计命名假设何时及为何被采纳。
- 可测试的。你能指出仍依赖它的具体论文或系统。
- 脆弱的。最近技术或环境变化削弱了理由。

## 3. 技术B：回到目的

### 程序
1. 问：此任务面向用户的目标是什么？不是指标，是目标。
2. 问：领域为达目标构建了哪些中间步骤？
3. 问：对每个中间步骤，它是必需的，还是领域成长方式的偶然？
4. 折叠任何非严格必需的中间步骤，问结果长什么样。

### 回到目的揭示什么
- 因旧硬件体制需要而存在但现在不需要的步骤。
- 因原始工具只能在某抽象级别产出而存在的步骤。
- 因专家角色历史性分割任务而存在的步骤。

## 4. 工作示例：自适应查询处理
- **假设**："Database query plans must be fully determined before execution." 理由：成本模型期望静态统计和静态负载。1970 年代采纳。
- **变了什么**：负载和数据分布变动态；现代存储可廉价观察中间结果。
- **重构**：如查询计划可在执行期间基于观察数据变化呢？这打破静态计划假设，创造自适应查询处理研究项目。
- **影响**：数十年关于运行时重新优化、参数化查询计划、学习基数的后续工作。

## 5. 工作示例：代理驱动数据清洗
- **目标重访**：实际目标是使下游分析或建模正确。数据清洗是中间步骤。
- **步骤审计**：传统清洗写独立于下游任务的脚本。这在下游任务无法观察清洗决策时是必需的。
- **重构**：如 LLM 代理观察下游任务反馈并迭代重写清洗策略呢？中间步骤折叠为与下游任务的闭环。
- **影响**：代理驱动数据清洗成为新方向而非已有清洗管线的微调。

## 6. 常见误用
- **假设表演**：命名一个假设并假装打破它，而重构仍秘密依赖同一假设。检查你的重构是否在管线任何位置依赖该假设。
- **稻草人假设**：审计领域无人持有的假设。审计应针对活的共识，非历史观点。
- **无界重构**：提出需要尚不存在技术的重构。如重构需要我们五年后才有的东西，记录在 Hamming 规则列表上继续；不将其视为今天可行动的。
- **跳过理由审计**：如无法说出假设最初为何被采纳，你无法判断理由是否仍成立。
