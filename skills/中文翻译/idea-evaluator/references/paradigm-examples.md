## 1. 如何阅读这些示例

每个示例追溯一条已发表或广泛采用的工作线至其根部的颠覆式重构。对每个示例，识别相关原则（第一性原理、房间里的大象、技术周期、Hamming 规则）。目的是展示颠覆式重构在实践中长什么样，以及用真实先例校准范式跃迁分析。

示例 2、3、4 出现在 `handbook/02_Idea_Generation/2.3_进阶_如何做颠覆式创新.md` 中作为其所锚定原则的示例。

## 2. 示例 1：Transformer 架构
- **背景**：约 2017 年，机器翻译社区最强模型使用复杂 CNN 或 RNN/LSTM 架构，注意力为次要机制。
- **共识假设**：序列递归对建模长程依赖是必需的。
- **重构（第一性原理）**：如仅靠注意力就够了呢？Google 团队丢弃所有递归，提出纯注意力架构 Transformer。
- **结果**：基本上所有后续大语言模型的基础，NLP、视觉和语音的主导架构。
- **原则**：第一性原理（对递归的假设审计）加技术周期（GPU 算力使大型全注意力模型可行）。

## 3. 示例 2：自适应查询处理
- **背景**：传统数据库查询优化。
- **共识假设**：查询计划必须在执行前完全确定；优化器使用静态统计。
- **重构（第一性原理）**：如统计在执行期间变化呢？让计划适应观察到的中间基数。
- **结果**：关于运行时重新优化、渐进基数估计、参数化查询计划的多十年研究项目。
- **原则**：第一性原理（对静态计划的假设审计）加房间里的大象（生产系统总因估计误差看到计划失败；学术界回避了这点）。

## 4. 示例 3：代理驱动数据清洗
- **背景**：传统数据清洗使用独立于下游使用的独立脚本（规则、启发式、小模型）。
- **共识假设**：清洗是与下游任务解耦的预处理步骤。
- **重构（回到目的）**：清洗的目标是正确的下游分析。让 LLM 代理观察下游任务性能并迭代重写清洗策略。
- **结果**：代理驱动数据清洗成为独立于经典清洗的研究方向；任务条件化清洗将预处理步骤折叠为反馈环。
- **原则**：第一性原理（回到目的）加技术周期（LLM 代理使反馈环可行）。

## 5. 示例 4：多代理协作工作流
- **背景**：复杂业务任务的单一代理 LLM 系统。
- **边缘案例观察**：单一代理在多角色、长时间跨度任务（如端到端构建完整 Web 应用）上循环、幻觉或失控。
- **共识假设**：更多提示工程或更长上下文会修复多步失败。
- **重构（房间里的大象）**：单一代理失败不是提示调优问题；是协调问题。设计带角色分离和标准操作程序的多代理框架。
- **结果**：围绕代理编排、多代理框架、代理工作流、协调协议的研究项目。
- **原则**：房间里的大象（回避的长时间跨度多角色任务难题）加技术周期（LLM 代理可用性）。

## 6. 跨示例教训
- 四个示例都结合了四条原则中的两条。单原则重构通常较弱；最强颠覆式工作在假设、痛点、技术转变和重要问题间三角定位。
- 四个中有三个需要技术周期元素才可行动。无此转变，重构要么过早（技术尚不存在）要么太晚（社区已吸收）。
- 四个无一是一篇论文的贡献。每个都开启了跨年的研究项目。范式跃迁分析应瞄准项目级重构，非单篇论文的微调。
- 四个在当时都有风险。Transformer 论文面临怀疑；自适应查询处理最初被认为不切实际；代理驱动清洗仍有争议；多代理框架仍在证明价值。颠覆式工作与接受风险共存。
