每个示例将已发表的 Introduction 逆向工程为起草前应在脑中的六段计划。计划忠实于发表版论文，部分写作要点改述。来源为 `handbook/06_Case_Studies/6.1`、`6.2` 和 `6.3`。

## 2. 示例 A：Alpha-SQL（ICML 2025），技术类

### 类型定位

技术论文。Text-to-SQL 是有活跃 benchmark（Spider、BIRD）的老问题。贡献是方法：MCTS 推理时搜索。

第 3 段是一句话桥。

### 大纲

1. **背景与动机**。生产分析中的真实 Text-to-SQL 应用；运行示例：零售数据库上的多表聚合查询。已有开源 LLM SQL 生成器在复杂案例上挣扎。
2. **已有工作局限**：
   - L1：已有开源方法依赖单遍生成，在复杂 JOIN 推理上失败。
   - L2：微调方法昂贵且跨模式不泛化。
   - L3 不声称；论文仅用两条局限保持焦点。
3. **问题本质与目标**。硬约束：开源可部署无需微调。目标桥："Our goal is to improve complex-query SQL generation on open-source LLMs without fine-tuning."
4. **关键挑战**：
   - Ch1：枚举 SQL 候选时的决策空间爆炸。
   - Ch2：无训练批评者的奖励建模。
5. **方案概述**。Alpha-SQL 含 MCTS 引导推理和自监督奖励信号。模块 A 通过结构化搜索处理 Ch1。模块 B 通过执行反馈处理 Ch2。
6. **贡献**：
   1. MCTS 推理搜索用于 Text-to-SQL（第 3 节）。
   2. 来自执行反馈的自监督奖励设计（第 4 节）。
   3. 在 BIRD 和 Spider 上的实验，显示 N 点准确率提升（第 5 节）。

## 3. 示例 B：AFlow（ICLR 2025），带跨领域框架的技术类

### 类型定位

技术论文，框架化以强调更广维度跨领域移植（算子搜索用于代理工作流，借用自神经架构搜索）。

第 3 段简短过渡；关键想法权重在第 4 和 5 段。

### 大纲

1. **背景与动机**。代码生成 LLM 代理；运行示例：HumanEval 任务上代理工作流在算子组合错误时失败。
2. **已有工作局限**：
   - L1：仅提示工程产出脆弱工作流。
   - L2：单代理架构不捕获算子组合。
   - L3：手工设计工作流不跨任务家族泛化。
3. **问题本质与目标**。硬约束：工作流设计须泛化到未见算子。目标桥："Our goal is to automate workflow design for code-generation agents."
4. **关键挑战**：
   - Ch1：算子图搜索空间组合爆炸。
   - Ch2：工作流的评估信号离散且稀疏。
5. **方案概述**。AFlow 含算子图搜索（借用自 NAS）和通过代码执行的结构化奖励。模块 A 处理 Ch1；模块 B 处理 Ch2。
6. **贡献**：
   1. 将代理工作流设计框架化为算子图搜索（第 2 节）。
   2. AFlow 搜索算法，执行反馈引导（第 3 节）。
   3. 在 HumanEval、MBPP 和相邻 benchmark 上的评估，显示对手工和提示工程工作流的一致提升（第 4 节）。

## 4. 示例 C：LEAD（VLDB 2026），新问题/设定类

### 类型定位

新问题/设定论文。第 3 段承重：贡献是新设定"无额外推理的迭代数据选择"。

### 大纲

1. **背景与动机**。LLM 指令微调；数据质量胜过数量。运行示例：50k 样本指令语料库，迭代选择改善微调质量但每轮产生全数据集推理。
2. **已有工作局限**：
   - L1：非迭代选择不适应模型演化。
   - L2：迭代方法每轮需昂贵的全数据集推理。
3. **问题本质与目标**。硬约束：在已有微调环之上无额外推理预算。研究问题作为核心贡献："Can iterative selection benefits be preserved while eliminating repeated full-dataset inference?" 关键想法：用微调环中已计算的训练损失作为零开销效用信号。
4. **关键挑战**：
   - Ch1：从噪声训练损失轨迹中提取可靠效用信号。
   - Ch2：将选择信号集成到训练环中不扰动收敛。
5. **方案概述**。LEAD 框架，以实例级动态不确定性（IDU）作为效用信号；选择与训练同步内联运行。模块 A 通过统计去噪处理 Ch1；模块 B 通过延迟选择处理 Ch2。
6. **贡献**：
   1. 无额外推理的迭代数据选择的问题形式化（第 2 节）。
   2. 实例级动态不确定性信号及其理论分析（第 3、4 节）。
   3. LEAD 框架设计（第 3 节）。
   4. 多个指令微调 benchmark 上的大量实验，显示匹配或更好质量以低一个数量级成本（第 5 节）。

## 5. 示例教授什么

- Alpha-SQL 展示紧凑技术论文：三条贡献、两条局限、两个挑战。焦点致胜。
- AFlow 展示带跨领域框架的技术论文：三条贡献、三条局限、两个挑战。更广维度框架赢得 ICLR 位置而不改变类型。
- LEAD 展示新问题论文：第 3 段承重；贡献包含问题设定本身作为 C1；框架和方法是 C2-C4。
- 三者都有挑战到模块的一一映射；无一超过三个挑战。无一有模糊短语作为贡献。
- 三者在 C1 中引用已有工作时都在第 2 段 crediting 已有局限。
