# 论文类型定位：技术类 vs 新问题/设定类

## 目录

1. 为什么定位重要
2. 技术论文画像
3. 新问题/设定论文画像
4. 定位标准
5. 工作示例：Alpha-SQL、AFlow、LEAD

## 1. 为什么定位重要

论文类型定位决定 Introduction 的重心落在哪里。技术论文的叙事脊柱是关键想法；目标得一句话桥。新问题/设定论文的叙事脊柱是目标或问题形式化；关键想法从属于"为何此定义合理且可行"。

定位错误是常见 Introduction 失败。新问题论文写成技术论文会低权重其贡献。技术论文写成新问题论文会过度声称。

## 2. 技术论文画像

技术论文的核心贡献是解决已定义问题的新方法或机制。关键想法承载叙事。

信号：

- 问题已确立（已有命名 benchmark，已有工作丰富）。
- 贡献是"把 X 做得更好"，不是测量新东西或研究新设定。
- 审稿人会在同一问题上与最强已有方法比较。
- 实验聚焦于"我们的方法胜过基线"。

Introduction 权重分布：

- 第 1 段：150-200 词（运行示例必需）。
- 第 2 段：150-200 词（已有方法的具体局限）。
- 第 3 段：100-150 词（目标是桥；关键想法承重）。
- 第 4 段：150-200 词（挑战）。
- 第 5 段：150-200 词（方案模块）。
- 第 6 段：100-150 词（贡献）。

## 3. 新问题/设定论文画像

新问题/设定论文的核心贡献是定义社区尚未如此研究的问题，或已有问题中的新设定。目标或问题形式化就是贡献。

信号：

- 相邻问题已有工作但不是此特定框架。
- 贡献是思考空间的新方式，不是已有问题上的新方法。
- 实验旨在刻画新问题，而非超越已有排行榜。
- Introduction 包含特定的"Our Goal"或"Research Question"段落，承重。

Introduction 权重分布：

- 第 1 段：150-200 词。
- 第 2 段：150-200 词（局限展示为何已有框架遗漏此问题）。
- 第 3 段：200-250 词（目标或问题形式化是贡献；关键想法支撑"为何此定义合理"）。
- 第 4 段：100-150 词（挑战）。
- 第 5 段：150-200 词（实现该设定的方案模块）。
- 第 6 段：100-150 词（C1 是问题形式化）。

## 4. 定位标准

按顺序询问。第一个"是"决定类型。

1. 论文是否定义了社区尚未研究的问题或设定？如是，新问题/设定。
2. 论文主要贡献是否是已有 benchmark 上的新方法？如是，技术。
3. 论文主要贡献是否是新的 benchmark？如是，使用 `benchmark-paper-template`（单独插件）。
4. 论文是否提出方法同时也是问题重构？见下方混合情况。

## 5. 工作示例

### Alpha-SQL（ICML 2025）

类型：技术论文。

理由：Text-to-SQL 问题已确立；论文贡献 MCTS 推理机制改善 SQL 生成。目标是短桥（"we improve SQL generation accuracy on complex queries"）。关键想法（MCTS 推理时搜索）承载叙事。

Introduction 段落权重匹配技术画像：第 3 段短；第 4 和 5 段承载细节。

### AFlow（ICLR 2025）

类型：带跨领域框架的技术论文。

理由：代理工作流设计问题存在，但尚未被框架化为算子图上的搜索问题。论文可以说是混合情况。其发表版 Introduction 以关键想法而非目标开头，因此档案案例研究归类为带更广维度框架的技术论文。

如作者更重第 3 段使"workflow-as-a-search-space"成为贡献，论文可定位为新问题。两种框架都可辩护。选择影响论文与哪些审稿人产生共鸣。

### LEAD（VLDB 2026）

类型：新问题/设定论文。

理由：已有迭代数据选择工作假设每轮全数据集推理。LEAD 将设定重定义为"无额外推理的迭代选择"。新设定是核心贡献；方法（来自训练损失的实例级动态不确定性）支撑设定为何可行。

Introduction 第 3 段承重：目标和研究问题"Can iterative benefits be kept while eliminating repeated full-dataset inference?" 是头条贡献。

## 6. 混合情况

论文可以合理地同时贡献新方法和新问题框架。此时：

- 选择论文交付最好的贡献。
- 次要贡献放在第 6 段但不在第 3 段争叙事空间。
- 不要试图同时框定为两者；Introduction 会失焦。
- 如两种贡献确实等强，考虑拆分为两篇或写期刊版。

混合情况线索：作者不确定哪种框架更强。如一种框架在投稿前讨论中持续引发更清晰的审稿人兴奋，选那种。如两种等强，拆分论文。
